# Руководство пользователя GrowVision CLI

Консольный клиент GrowVision (`clients/cli`) предназначен для оперативного мониторинга, управления гидропонными установками, камерами и освещением, а также для ручной фотосъёмки и экспорта видео таймлапсов.

---

## 1. Установка и настройка

### 1.1. Конфигурация клиента (`clients/cli/.env`)
Перед первым запуском настройте параметры подключения к серверу:

```bash
cp clients/cli/.env.example clients/cli/.env
```

Параметры в `clients/cli/.env`:
- `SERVER_URL` — базовый адрес сервера GrowVision (по умолчанию `http://127.0.0.1:8000`).
- `CLIENT_API_KEY` — секретный API-ключ клиента (должен совпадать с ключом сервера).
- `CLI_DEBUG` — опциональный флаг (`0` или `1`) для подробного вывода HTTP-запросов.

### 1.2. Сессия клиента
CLI автоматически генерирует уникальный идентификатор устройства (`cli_<uuid4>`) и сохраняет его в файле `~/.growvision_cli.json`. Он используется сервером для привязки сессии авторизации к конкретному терминалу.

---

## 2. Режимы работы

### 2.1. Интерактивная оболочка (`shell`)
Рекомендуемый способ повседневной работы. Оболочка запускается по умолчанию при вызове CLI без аргументов:

```bash
./clients/cli/.venv/bin/python -m clients.cli.main
# или
./clients/cli/.venv/bin/python -m clients.cli.main shell
```

Откроется приглашение:
```text
GrowVision 0.1.0
Интерактивная оболочка. Введите команду или 'help'. Для выхода введите 'exit' или 'quit'.

growvision> 
```
Внутри оболочки команды вводятся напрямую без префикса:
```text
growvision> unit list
growvision> snap take 1
growvision> exit
```

### 2.2. Одиночные вызовы из командной строки
Для автоматизации и использования в скриптах команды можно вызывать напрямую:

```bash
./clients/cli/.venv/bin/python -m clients.cli.main unit list
./clients/cli/.venv/bin/python -m clients.cli.main snap take 1 --download ./photos
```

## 3. Роли и авторизация

Система разграничивает доступ по трём ролям:
1. **Гость** (по умолчанию, без пароля) — просмотр списка активных установок и плановых кадров.
2. **Biologist** — редактирование агрономических параметров (название, культура), ручная тестовая съёмка, экспорт таймлапсов.
3. **Developer** — полный доступ: управление реле основного света и вспышки, сканирование и привязка камер, удаление установок, телеметрия Raspberry Pi 5, настройка расписания и режима отладки.

---

## 4. Справочник команд

### 4.1. Глобальные команды
- `help` — вывод общей справки по системе и командам.
- `version` — отображение версии сервера GrowVision.
- `--verbose` / `-v` — флаг для вывода отладочной информации по HTTP-запросам.

---

### 4.2. Раздел `auth` — Авторизация и сессия
Для CLI разрешён вход **только для роли Developer** (постоянный пароль разработчика). Биологи авторизуются в Telegram-боте по одноразовым кодам, создаваемым разработчиком.

- `auth info` — справка по командам раздела.
- `auth login` — вход разработчика. Логин и пароль запрашиваются безопасно (пароль скрыт при вводе).
- `auth status` — просмотр текущей активной роли и времени сессии.
- `auth logout` — завершение текущей сессии (перевод в неактивную, возврат к роли Гость).
- `auth invite create [--role biologist]` — создание одноразового кода доступа для входа биолога в Telegram-бот (срок действия 10 минут).
- `auth invite list` — список всех действующих неиспользованных кодов приглашений.
- `auth invite revoke <invite_id>` — досрочный отзыв кода приглашения.
- `auth sessions` — мониторинг всех сессий пользователей (активные 🟢, завершённые ⚪️) с типами клиентов, именами и датами активности.
- `auth kick <session_id>` — принудительное завершение сессии любого пользователя.

---

### 4.3. Раздел `unit` — Гидропонные установки
Аргумент `<target>` поддерживает 3 формата:
1. Числовой ID: `unit show 1`
2. Точное название: `unit show "Бокс №1"`
3. Ключевое слово `all`: `unit show all` (карточки всех активных установок).

Команды:
- `unit info` — справка по разделу.
- `unit list [--archived / -a]` — таблица всех установок. Колонки автоматически адаптируются под роль (для Developer отображаются GPIO-пины и привязанные камеры).
- `unit show <target>` — подробная карточка установки с параметрами, размером ArUco-маркера и списком камер.
- `unit add [--name .. --culture .. --light-pin .. --flash-pin .. --aruco-mm .. --delay ..]` — добавление новой установки (Developer). Если параметры не указаны флагами, они будут запрошены интерактивно. Опция `--delay` задаёт индивидуальную задержку стабилизации света (0.0..30.0 с).
- `unit edit <target> [параметры]` — редактирование параметров установки. Флаг `--clear-aruco` сбрасывает маркер, `--delay <сек>` задаёт индивидуальную задержку съёмки, `--clear-delay` сбрасывает её на общесистемную.
- `unit delay <target> [seconds] [--default]` — быстрая настройка задержки съёмки для конкретной установки или возврат к общесистемной (`--default`).
- `unit archive <target> [-y]` — перевод установки в архив (Developer). Все привязанные камеры автоматически отвязываются.
- `unit delete <target> [-y]` — полное удаление установки (Developer). Для активных установок допустимо только если нет сохранённых снимков; для архивных установок разрешено удаление при любом количестве кадров (камеры отвязываются, записи в базе данных и все файлы медиа на диске удаляются).

---

### 4.4. Раздел `camera` — Камеры Raspberry Pi
Команды раздела доступны только роли **Developer**:
- `camera info` — справка по разделу.
- `camera list` — список всех зарегистрированных камер со статусами online/offline и привязками.
- `camera scan` — запуск аппаратного сканирования USB/CSI-камер на Raspberry Pi. Выводит перечень всех обнаруженных камер с подсказками по привязке.
- `camera bind <камера> <установка>` — привязка камеры к установке (по ID или Hardware ID камеры).
- `camera unbind <камера>` — отвязка камеры от установки.

---

### 4.5. Раздел `light` — Освещение и проверка реле
Команды раздела доступны только роли **Developer**:
- `light info` — справка по разделу.
- `light main <target> <on|off>` — ручное включение/выключение основного освещения на установке или всех активных (`all`).
- `light flash <target> <on|off>` — ручное включение/выключение подсветки для фото (вспышки).
- `light test <target>` — кратковременное (3 секунды) включение обоих реле для тестирования аппаратной части.

---

### 4.6. Раздел `snap` — Съёмка и видео таймлапсов
Доступно для **Biologist** и **Developer**:
- `snap info` — справка по разделу.
- `snap take <target> [--download <папка>]` — выполнение внепланового тестового снимка. Выводит таблицу полученных кадров (время, площадь растения, ссылки на оригинал и разметку нейросетью). При передаче `--download` файлы оригиналов и разметки скачиваются в указанную директорию.
- `snap video <target> [--camera-id <id>] [--step N] [--out путь]` — генерация MP4-таймлапса из всех плановых кадров установки.
  - Поддерживает архивные установки (можно выгрузить историю завершённого цикла).
  - С флагом `--step N` экспортируется каждый N-й кадр (с сохранением первого и последнего).
  - Если в истории установки есть только 1 плановый кадр, автоматически сохраняется JPEG-фотография.
  - Скачивание видео происходит во временный файл `.part`, предотвращая повреждение при сетевом обрыве.

---

### 4.7. Раздел `system` — Телеметрия и настройки
Доступно для **Developer**:
- `system info` — справка по разделу.
- `system status` — сводная информация: статус подключения RPi, время последнего сигнала (heartbeat), текущие настройки (интервал, задержка съёмки, режим отладки), а также телеметрия железа Raspberry Pi 5 (аптайм, температура CPU, загрузка процессора, использование RAM, свободное место на диске, размер офлайн-очереди).
- `system schedule <hours>` — изменение интервала плановой периодической фотосъёмки (в часах, целое число ≥ 1).
- `system delay <seconds>` — изменение глобальной задержки стабилизации света перед съёмкой (0.0..30.0 с, по умолчанию 1.5 с).
- `system debug <on|off>` — включение или отключение расширенного режима отладки с выводом логов RPi.

---

## 5. Диагностика и устранение неполадок

- При ошибках CLI выводит понятное сообщение на русском языке в `stderr` с дословным текстом от сервера и рекомендацией по исправлению.
- Для просмотра точных сетевых запросов и ответов сервера используйте глобальный флаг `--verbose` (`-v`) или переменную `CLI_DEBUG=1` в `clients/cli/.env`.

## 6. Telegram-бот GrowVision (`clients/telegram_bot`)

Telegram-бот GrowVision предоставляет мобильный графический интерфейс для оперативного мониторинга растений, управления гидропоникой, просмотра галереи кадров и экспорта таймлапсов прямо из мессенджера Telegram.

### 6.1. Настройка и запуск бота

#### Конфигурация окружения (`clients/telegram_bot/.env`)
Перед запуском создайте файл конфигурации:
```bash
cp clients/telegram_bot/.env.example clients/telegram_bot/.env
```

Заполните переменные в `clients/telegram_bot/.env`:
- `TELEGRAM_BOT_TOKEN` — токен бота, полученный у `@BotFather`.
- `SERVER_URL` — базовый URL сервера GrowVision (по умолчанию `http://127.0.0.1:8000`).
- `CLIENT_API_KEY` — секретный ключ клиента (должен совпадать со значением `CLIENT_API_KEY` на сервере).
- `BOT_LOG_LEVEL` — уровень логирования (`INFO` или `DEBUG`, по умолчанию `INFO`).
- `TELEGRAM_PROXY` — опциональный HTTP/SOCKS5 прокси для обращений к Telegram API (например, `socks5://127.0.0.1:1080` или `http://proxy:8080`). Учётные данные маскируются в логах.
- `BOT_DEBUG_LOG` — включение структурированного JSONL-журнала событий в `clients/telegram_bot/logs/` (`true`/`false`, по умолчанию `false`). Журнал ротируется (хранение 7 дней), пароли и токены автоматически маскируются.

> [!NOTE]
> При старте бот регистрирует системное меню команд в интерфейсе Telegram (`/start`, `/help`, `/version`, `/login`, `/cancel`).
> Если связь с `api.telegram.org` отсутствует (при старте или при обрыве во время long polling), бот не завершает работу, а выполняет повторные попытки со ступенчатыми паузами (5, 10, 20, 40 с, далее каждые 60 с), выводя в журнал диагностическое предупреждение `Нет доступа к api.telegram.org: проверьте VPN или TELEGRAM_PROXY`. При восстановлении связи работа возобновляется автоматически.

> [!NOTE]
> При отсутствии любой из обязательных переменных (`TELEGRAM_BOT_TOKEN`, `SERVER_URL`, `CLIENT_API_KEY`) бот завершает работу с информативным сообщением об ошибке в консоли, перечисляя недостающие параметры. Секреты (токен и API-ключ) маскируются в логах.

#### Установка зависимостей и запуск
```bash
# Создание виртуального окружения и установка зависимостей
python3 -m venv clients/telegram_bot/.venv
./clients/telegram_bot/.venv/bin/pip install -r clients/telegram_bot/requirements.txt

# Запуск бота (режим long-polling)
./clients/telegram_bot/.venv/bin/python -m clients.telegram_bot.main
```

### 6.2. Роли и возможности в Telegram-боте

Бот поддерживает ту же ролевую модель, что и вся система:
1. **Гость** (по умолчанию, без авторизации):
   - Просмотр списка активных установок и их параметров.
   - Просмотр последнего планового кадра таймлапса (полная галерея с пагинацией доступна биологам и разработчикам).
   - Информационные команды (`/help`, `/version`).
   - Кнопка авторизации `[ 🔑 Войти ]` / команда `/login`.
2. **Биолог (Biologist)**:
   - Все возможности Гостя.
   - Интерактивная галерея плановых кадров с перелистыванием и переключением слоёв оригинал/разметка.
   - Ручная внеплановая фотосъёмка (`📸 Сделать снимок`) с получением качественного raw-снимка.
   - Сборка и отправка MP4-таймлапса с автоматическим контролем лимита 50 МБ.
   - Редактирование агрономических названий и выращиваемых культур установок.
3. **Разработчик (Developer)**:
   - Полный доступ ко всем функциям системы.
   - Ручная внеплановая фотосъёмка с получением альбома (сырой кадр + разметка нейросетью) и диагностического блока `🐞 DEBUG` (команда и лог RPi).
   - Управление освещением (`💡 Свет и реле`): ручное включение/выключение основного света, подсветки (вспышки), 3-секундный тест реле, настройка задержки съёмки.
   - Управление камерами (`📷 Камеры`): сканирование портов RPi 5, просмотр привязанных камер (включая оффлайн с пометкой 🔴), привязка и отвязка.
   - Полнофункциональный мастер создания установок (5 шагов с валидацией GPIO 0..53), редактирование всех полей (включая задержку съёмки и маркер ArUco), архивация и удаление (включая архивные установки с кадрами).
   - Системное меню (`⚙️ Система`): статус сервера и Raspberry Pi 5 (аптайм, температура CPU, RAM, диск, офлайн-очередь), изменение интервала автосъёмки, глобальной задержки съёмки, переключение `debug_mode`.

### 6.3. Безопасная авторизация, профиль и команды навигации

Авторизация в боте реализована через двухэтапный FSM-сценарий:
1. Пользователь нажимает `[ 🔑 Войти ]` или вводит `/login`.
2. Бот запрашивает логин пользователя.
3. Бот запрашивает пароль.
4. **Скрытие пароля:** Сразу же после отправки сообщения с паролем бот немедленно удаляет это сообщение из чата Telegram через `delete_message`, предотвращая компрометацию учётных данных на экране или в истории переписки.
5. При успешном входе главное меню обновляется в соответствии с полученной ролью (`Гость`, `Биолог`, `Разработчик`).
6. В любой момент авторизацию можно отменить командой `/cancel` или кнопкой `[ ❌ Отмена ]`.
7. **Профиль пользователя и изменение имени:** Меню `[ 👤 Профиль / Выход ]` или прямая команда `/profile` отображают актуальные данные учётной записи из `GET /api/auth/me`: логин, роль, точное время авторизации и время последней активности. Кнопка `[ ✏️ Изменить имя ]` позволяет обновить отображаемое имя пользователя (Имя и Фамилия). Разработчик также может переименовать любого пользователя через раздел «👥 Сессии» или команду CLI `auth rename <session_id> <new_name>`. При отсутствии активной сессии предлагается войти.
8. **Подсказка при неизвестных сообщениях:** Если пользователь отправляет произвольный текст вне FSM-диалога, бот возвращает понятную подсказку: `Не понял. Список команд: /help`.

---

### 6.4. Просмотр кадров и таймлапсов

- **Галерея снимков:** При просмотре кадров установки бот открывает плановые кадры:
  - Для роли **Гость**: отображается только последний плановый кадр с кнопкой `[ ⬅️ Закрыть ]` (без возможности листания всей истории).
  - Для ролей **Biologist** и **Developer**: доступна полная галерея с инлайн-навигацией:
    - `⏮ / ◀️` и `▶️ / ⏭` — постраничное листание по одному кадру.
    - `🖼 Показать оригинал` / `🧠 Показать разметку` — мгновенное переключение слоёв без спама новыми сообщениями.
  - При одновременной съёмке на несколько камер бот предлагает выбрать ракурс конкретной камеры.
- **Сборка видео-таймлапса:**
  - При запуске сборки видео бот отображает анимированный статус ожидания («⏳ Собираю видео-таймлапс...»).
  - Если в истории установки зафиксирован только **1 плановый кадр**, бот отправляет JPEG-фотографию с пояснением: *«Плановый кадр пока один, видео не собрано»*.
  - **Контроль лимита Telegram (50 МБ):** Если итоговый MP4-файл превышает 50 МБ, бот автоматически запускает цикл прореживания (до 5 попыток со `step = 2, 4, 8, 16, 32`), обновляя статус для пользователя. Если видео укладывается в 50 МБ, оно отправляется в чат с пометкой о применённом шаге прореживания. Если даже при `step = 32` размер превышает лимит, бот сообщает об этом и рекомендует скачать полное видео через консольный клиент: `snap video <id>`.
  - **Защита от параллельных сборок:** Для каждого пользователя блокируется одновременный запуск более одного процесса рендеринга видео.

---

### 6.5. Ручная фотосъёмка (`📸 Сделать снимок`)

- Доступна для ролей **Biologist** и **Developer**.
- Поддерживает выбор конкретной установки или всех активных установок одновременно.
- На время выполнения съёмки, переключения реле и детекции нейросетью бот выводит статус ожидания: *«⏳ Делаю снимок, подождите...»*.
- **Разделение по ролям:**
  - Для роли **Biologist**: отправляется качественный raw-снимок без разметки нейросетью через `send_photo`.
  - Для роли **Developer**: отправляется альбом (медиагруппа) из двух фотографий (сырой снимок + разметка нейросетью).
- Для роли Developer при включённом `debug_mode` в подпись добавляется блок `🐞 DEBUG` с деталями вызова оборудования (выводятся поля `Команда:` и `Лог:` с аппаратного агента).

---

### 6.6. Управление оборудованием (Developer)

- **Свет и вспышка:** Удобное меню с кнопками включения и выключения основного освещения и фото-подсветки для каждой установки или всех одновременно. Состояние реле программно синхронизируется по номеру GPIO-пина: если две установки подключены к одной линии освещения, переключение тумблера в одной установке немедленно обновляет статус и во второй (во всех клиентах: Bot, CLI, Web).
- **Тест реле:** Кнопка `⚡ Тест реле (3 сек)` включает оба канала на 3 секунды для визуальной проверки проводки на стенде.
- **Камеры установки:** Кнопка `📷 Камеры установки` в карточке выводит список привязанных камер с наглядными индикаторами (🟢 online / 🔴 offline) и быстрыми ссылками на карточки камер.
- **Сканирование камер:** Кнопка `🔄 Сканировать порты RPi` опрашивает физические шины Raspberry Pi 5 и возвращает только реально обнаруженные в данный момент камеры (отключенные устройства не выводятся в результатах поиска, но остаются в базе со статусом оффлайн).
- **Задержка съёмки (`capture_delay_sec`):** Кнопка `⏱ Задержка съёмки` доступна в меню «💡 Свет и реле» (общесистемная настройка) и в карточке установки (индивидуальная). Предусмотрены быстрые пресеты (`0.5 с`, `1.5 с`, `3.0 с`, `5.0 с`, а для установки — `🔄 Использовать общую`), а также точный ручной ввод в диапазоне от `0.0` до `30.0` секунд без сброса FSM-диалога при ошибках.

### 6.7. Мастер создания и редактирования установок (Developer)

- **Проверка уникальности имени:** На шаге 1 мастер мгновенно сверяет введённое имя со списком всех существующих установок (включая архивные). Если имя уже занято, бот предупреждает пользователя и просит ввести другое имя без сброса FSM-состояния мастера.
- **Общие GPIO-пины:** Несколько установок могут использовать один и тот же пин (например, одну общую фитолампу на несколько лотков). При совпадении пина с другой активной установкой сохранение не блокируется, а выводится предупреждение: `⚠️ Пин X уже занят («Установка 1»). Реле будут общими.`. При этом пины света и вспышки внутри одной установки не могут совпадать.
- **Валидация GPIO-пинов:** На шагах выбора пинов основного света и вспышки бот проверяет диапазон `0 <= pin <= 53`. Ввод некорректных значений выводит понятную ошибку и сохраняет текущий шаг мастера.
- **Настройка маркера ArUco на шаге 5:** Пользователь может ввести точный размер стороны маркера в мм (например, `50.0`) либо нажать кнопку `[ ⏭ Пропустить ]`. При пропуске размер маркера остаётся не заданным (`null`), а площадь растений будет отображаться и рассчитываться в пикселях (`px`).
- **Карточка установки:** В карточке отображаются актуальные поля API (`culture_name`, `last_area_display`, `aruco_size_mm`, `capture_delay_sec`, `created_at`, список привязанных камер). После изменения или сброса значений карточка мгновенно обновляется. Все пользовательские строки надёжно экранируются.
- **Удаление архивных установок:** В соответствии с правилами системы, активную установку с накопленными кадрами удалить нельзя (возвращается 409 Conflict). Если перевести установку в архив, её удаление разрешено: отвязываются камеры, очищаются записи в БД и удаляются все связанные медиафайлы с сервера.

### 6.8. Фиксация дефектов на лету и журнал отладки (BUG-LOG)

В GrowVision Telegram-бот встроен удобный механизм оперативной фиксации багов и диагностический CLI:
1. **Быстрая баг-заметка в чате:** Если отправить боту любое текстовое сообщение, начинающееся с звёздочки `*` (например, `*почему-то кнопка отмены серая`), бот автоматически:
   - Сохраняет текст заметки вместе с 20 последними событиями (входящие апдейты, нажатия кнопок, вызовы Client API) из кольцевого буфера памяти.
   - Отвечает подтверждением: `Записано: BUG-LOG-N` (где `N` — порядковый номер дефекта).
   - **Не сбрасывает FSM-состояние:** если вы находились в процессе заполнения формы или мастера создания, текущий шаг полностью сохраняется.
2. **Структурированный JSONL-журнал (`BOT_DEBUG_LOG=true`):** Все события и баг-заметки сохраняются в папке `clients/telegram_bot/logs/` с автоматической ротацией (хранение 7 дней). Секретные данные (пароли и токены) маскируются.
3. **CLI-утилита `bug_log`:** Для быстрого просмотра зафиксированных дефектов доступна встроенная утилита:
   ```bash
   # Список всех зафиксированных баг-заметок
   clients/telegram_bot/.venv/bin/python -m clients.telegram_bot.tools.bug_log list

   # Подробный просмотр конкретной заметки и 20 событий перед ней
   clients/telegram_bot/.venv/bin/python -m clients.telegram_bot.tools.bug_log show 1

   # Просмотр последних записей общего журнала событий
   clients/telegram_bot/.venv/bin/python -m clients.telegram_bot.tools.bug_log tail -n 30
   ```

## 7. Тестирование без ожидания

Раздел предназначен для быстрой отладки системы и проверки алгоритмов компьютерного зрения, таймлапсов и генерации видео без ожидания реальных суточных астрономических интервалов и без необходимости подключения физического оборудования.

### 7.1. Запуск без реального оборудования (стенд на ПК)

Для запуска полного стека GrowVision локально на рабочей станции достаточно запустить три компонента в отдельных терминалах:

1. **Сервер FastAPI:**
   ```bash
   server/.venv/bin/uvicorn server.main:app --host 127.0.0.1 --port 8000
   ```
2. **Edge-агент в mock-режиме:**
   В файле `edge_agent/.env` (или через переменные окружения) установите:
   ```env
   SERVER_URL=http://127.0.0.1:8000
   EDGE_API_KEY=your-edge-api-key
   HARDWARE_MODE=mock
   ```
   Запуск агента:
   ```bash
   edge_agent/.venv/bin/python -m edge_agent.main
   ```
   В mock-режиме агент генерирует синтетические кадры разрешением 1280x720 с контрастным маркером ArUco `DICT_4X4_50` id 0 и динамически растущим растением, вычисляет замеры площади через порог HSV и детекцию ArUco, и не требует реальных GPIO и камер.
3. **Клиенты (CLI / Telegram-бот):**
   ```bash
   # Интерактивная консоль CLI:
   clients/cli/.venv/bin/python -m clients.cli.main shell

   # Или Telegram-бот:
   clients/telegram_bot/.venv/bin/python -m clients.telegram_bot.main
   ```

### 7.2. Ускоренный тестовый интервал съёмки (`TEST_CAPTURE_INTERVAL_SEC`)

Для проведения ускоренных тестов с реальными камерами и реле на стенде Raspberry Pi без многочасового ожидания предусмотрена переменная окружения `TEST_CAPTURE_INTERVAL_SEC`:

- **Параметр:** `TEST_CAPTURE_INTERVAL_SEC` (целое число секунд, минимум 10 с). При значении менее 10 агент завершается с ошибкой валидации при старте.
- **Поведение:** Если переменная задана, плановая автосъемка запускается циклически каждые N секунд от момента старта агента, полностью игнорируя астрономическую сетку UTC и серверный интервал часов. Работает идентично как в `HARDWARE_MODE=rpi`, так и в `HARDWARE_MODE=mock`.
- **Логирование:** При старте агента выводится явное предупреждение `WARNING: ТЕСТОВЫЙ ИНТЕРВАЛ СЪЁМКИ: N с`, а факт интервала фиксируется в логе каждой плановой съемки (`[TEST_INTERVAL=N s]`).
- **Пример сценария проверки:**
  ```bash
  # Запуск агента на RPi с интервалом съёмки 30 секунд:
  TEST_CAPTURE_INTERVAL_SEC=30 edge_agent/.venv/bin/python -m edge_agent.main
  ```
  Через 10 минут агент сделает 20 плановых кадров с реальной вспышкой и камерой, после чего в CLI или боте можно сразу протестировать сборку видео таймлапса:
  ```bash
  clients/cli/.venv/bin/python -m clients.cli.main snap video 1
  ```

### 7.3. Посев истории кадров симулятором (`edge_agent.simulator seed`)

Для мгновенного наполнения базы данных кадрами за прошедшие дни и проверки видео, графиков роста и галереи используется встроенный CLI-симулятор:

```bash
python -m edge_agent.simulator seed --installation <id> [--frames 48] [--step-hours 1] [--start <UTC>] [--cameras all|<hardware_id,...>] [--from-dir <папка>]
```

#### Параметры команды:
- `--installation <id>` *(обязательный)* — числовой ID активной гидропонной установки.
- `--frames <N>` — количество кадров на каждую камеру (по умолчанию 48).
- `--step-hours <H>` — шаг по времени между кадрами в часах (по умолчанию 1.0).
- `--start <ISO-время>` — время первого кадра в формате UTC (например `2026-11-20T00:00:00Z`). Если не указано, вычисляется назад от текущего времени (`now - frames * step_hours`).
- `--cameras <all | id1,id2>` — список привязанных `hardware_id` камер через запятую или `all` для всех привязанных камер (по умолчанию `all`).
- `--from-dir <папка>` — путь к каталогу с локальными JPEG-снимками. При нехватке снимки берутся циклически по кругу в алфавитном порядке.

#### Режимы генерации кадров:
1. **Синтетическая генерация (по умолчанию, без `--from-dir`):**
   - Генерирует кадры 1280x720 средствами OpenCV;
   - На кадр наносится маркер ArUco `DICT_4X4_50` (id 0) с белой контрастной каймой;
   - Зеленое растение растет строго монотонно от кадра к кадру;
   - Для разных камер применяются различные ракурсы и смещения;
   - Автоматически рассчитывается площадь растений по порогу HSV и площадь маркера ArUco через `cv2.aruco`.
2. **Посев из каталога (`--from-dir /path/to/photos`):**
   - Берет реальные JPEG-фотографии из папки, циклически назначая им рассчитанные временные метки;
   - Замеры вычисляются по содержимому каждого файла.

#### Особенности и безопасность:
- **Идемпотентность:** Повторный запуск команды с тем же временем `--start` безопасен — сервер распознает существующие кадры по уникальному ключу `(installation_id, camera_id, captured_at)` и возвращает HTTP 200 без создания дубликатов.
- **Валидация оборудования:** Симулятор проверяет регистрацию камер и их привязку к установке. Если камера не привязана, выводится информативное сообщение об ошибке.

## 8. Веб-интерфейс GrowVision (Web SPA)

Полноценный веб-клиент GrowVision (`clients/web/`) работает в любом современном браузере на ПК и мобильных устройствах (адаптивность от 360 px) по адресу:
```text
http://<адрес_сервера>:8000/
```

### 8.1. Архитектура и безопасность
- **Чистый стек без внешних зависимостей:** HTML5, CSS3, ES-модули JavaScript. Страница работает автономно в локальной сети без подключения к интернету и без внешних CDN.
- **Cookie-сессии:** Авторизация осуществляется через безопасную `HttpOnly`-cookie (`SameSite=Lax`). Секретный API-ключ (`X-Client-Key`) в браузерный JS не передаётся, что гарантирует защиту от утечек и XSS.

### 8.2. Ролевая модель в веб-интерфейсе
1. **Гость (без авторизации):**
   - Просмотр списка активных и архивных гидропонных установок;
   - Просмотр плановых кадров в интерактивном плеере таймлапса;
   - Кнопка «🔑 Войти» в шапке.
2. **Биолог:**
   - Вход по 6-значному одноразовому коду доступа;
   - Просмотр и редактирование параметров установок (название, культура);
   - Выполнение ручных снимков растений (`raw`);
   - Управление тумблерами света и вспышки;
   - Плеер таймлапса и сборка/скачивание MP4-видео;
   - Изменение своего отображаемого имени (Имя и Фамилия) прямо из шапки профиля.
3. **Разработчик:**
   - Вход по постоянному паролю разработчика;
   - Полный CRUD установок (создание, настройка пинов 0..53 с предупреждениями об общих пинах, архивация, удаление);
   - Управление камерами (сканирование USB/CSI камер с выводом debug-логов, привязка/отвязка, переименование);
   - Тестирование релейных линий («⚡ Тест реле»);
   - Управление сессиями (генерация кодов для биологов с TTL 10 мин, список всех сессий, переименование и принудительное завершение / кик);
   - Системный мониторинг Raspberry Pi (uptime, CPU, RAM, температура, диск) и тумблеры `debug_mode` / `auto_capture`;
   - Вкладка **«💻 Терминал»** — интерактивная консоль команд GrowVision (`help`, `status`, `unit`, `cam`, `light`, `flash`, `snap`, `relay-test`, `auth`, `sys`, `clear`) с историей ввода стрелками `↑` и `↓`.

### 8.3. Интерактивный плеер таймлапса
- **Автоопределение камер:** Если несколько камер снимали параллельно (интервал ≤ 10 мин), в плеере автоматически появляется селектор выбора камеры; если камера одна — кадры идут единой непрерывной лентой.
- **Предзагрузка:** Кадры загружаются в фоновом пуле (до 6 параллельных запросов) с индикатором прогресса и однократным повтором при ошибке.
- **Управление воспроизведением:** Кнопки Play/Pause, ползунок таймлайна, покадровый шаг, переключение скорости (1x — 5 fps, 2x — 10 fps, 4x — 20 fps) и флажок зацикливания.
- **Слои:** Мгновенное переключение между слоем оригинала (`🖼 Оригинал`) и разметкой нейросети (`🧠 Разметка нейросети`) с сохранением текущей позиции кадра.
- **Метаданные кадра:** Точное время съёмки в локальном часовом поясе вашего устройства, расчётная площадь растения (`area_display`) и номер кадра.
- **Экспорт видео:** Генерация и скачивание готового MP4-видео с выбором камеры, шага кадров и длительности.
