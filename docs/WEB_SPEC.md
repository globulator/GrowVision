# GrowVision — Спецификация веб-плеера таймлапса (MVP)

Документ описывает публичный веб-клиент GrowVision (`clients/web/`): стек, структуру файлов, используемые эндпоинты, логику выбора установки и камеры, поведение плеера, ошибки и пустые состояния.

Опирается на `API_CONTRACT.md`, `DB_SCHEMA.md` и `REPO_AND_VERSIONING.md`. Логика камер и обработка кадров согласованы с `BOT_SPEC.md` и правилом сборки видео из `API_CONTRACT.md` (раздел 4.5).

---

## 1. Назначение и архитектурные ограничения

- **Статус документа:** защищённый архитектурный документ (меняется только с согласия пользователя, `REPO_AND_VERSIONING.md`, раздел 5.3).
- **Назначение:** публичный просмотр плановых кадров установок в виде таймлапса. Только чтение, без входа и без ролей (всегда роль Гость).
- **Стек:** чистые HTML, CSS и JavaScript. Node.js, сборщики, фреймворки (React и т. п.), внешние CDN и веб-шрифты **не используются**: страница должна работать в локальной сети без интернета. Шрифты системные.
- **Структура `clients/web/`:**
  ```text
  clients/web/
  ├── index.html      # Разметка двух экранов: список установок и плеер
  ├── style.css       # Стили (адаптивная вёрстка: телефон от 360 px и ПК)
  └── app.js          # Вся логика: API-обёртка, состояние, плеер, интерфейс
  ```
- **Раздача:** страницу отдаёт сам сервер FastAPI через `StaticFiles` (`REPO_AND_VERSIONING.md`, раздел 4). Адрес один и тот же, поэтому CORS не нужен, а все пути в коде **относительные**: `/api/...` и `/media/...`.
- **Изоляция:** веб не импортирует код `server/`, `edge_agent/`, `shared/`, не имеет `.env` и секретов. Заголовки авторизации (`X-Client-Key`, `X-Client-Type`, `X-External-Id`) **не отправляются**.
- **Язык интерфейса:** русский, без технического сленга.

## 2. Используемые эндпоинты

Все публичные (роль Гость, `API_CONTRACT.md`, раздел 1.1):

| Эндпоинт | Назначение |
| :--- | :--- |
| `GET /api/installations?include_archived=true\|false` | Список установок для главного экрана. |
| `GET /api/timelapse/{installation_id}/frames` | Все плановые кадры установки (без пагинации, порядок `captured_at ASC`). |
| `GET /api/version` | Версия сервера для подвала страницы. |

- Картинки берутся по `raw_url` и `annotated_url` из ответа `frames` (пути вида `/media/...`).
- Параметр `camera_id` веб не использует: все кадры загружаются одним запросом, а фильтрация по камере выполняется в браузере.
- `GET /api/installations/{id}` не нужен: список уже содержит все публичные поля.

---

## 3. Экран «Список установок»

- Карточка установки: название, культура, последняя площадь (`last_area_display` или `—`), значок `Архив` для архивных.
- Флажок `Показать архивные` (по умолчанию выключен): при включении список запрашивается с `include_archived=true`. Так в вебе можно посмотреть историю завершённых циклов.
- Нажатие на карточку открывает экран плеера.
- Пустой список: `Установок пока нет`.
- В подвале: `Версия системы: <server_version>` (если `GET /api/version` не ответил, строка скрывается без ошибки).

## 4. Экран «Плеер»

Шапка: кнопка `← К списку`, название и культура установки, кнопка `🔄 Обновить` (повторно запрашивает `frames`, сохраняя выбранные камеру и слой; докачиваются только новые кадры).

### 4.1. Выбор камеры

Гостю список камер установки недоступен, поэтому камеры определяются по `camera_id` в кадрах.

1. После загрузки `frames` клиент просматривает список по порядку и ищет **соседние** кадры с разными `camera_id`, снятые с разницей **не более 10 минут**. Это тот же признак «камеры снимали одновременно», что и у сборки видео на сервере.
2. Если такие кадры найдены, показывается селектор `Камера: [Камера <id> ▾]` (названий у Гостя нет, подписи по `ID`). Пункта «Все камеры» нет: кадры разных ракурсов не смешиваются. По умолчанию выбрана камера самого свежего кадра.
3. Если не найдены (камера одна или камера была заменена без пересечения по времени), селектора нет, а все кадры идут одной непрерывной лентой: при замене камеры таймлапс не рвётся.
4. Выбор камеры фильтрует уже загруженный список на стороне браузера и перезапускает предзагрузку для новой выборки (уже загруженные картинки не скачиваются повторно).

### 4.2. Предзагрузка кадров

- После выбора выборки браузер загружает **все** изображения выбранного слоя (по умолчанию `Оригинал`, `raw_url`). Загрузка идёт параллельно, не более 6 запросов одновременно; неудачный кадр повторяется один раз.
- Во время загрузки показывается индикатор `Загружено X из N` с полосой прогресса, а **все элементы управления заблокированы** (Play, ползунок, шаги, скорость, зацикливание, переключатель слоя, селектор камеры). Это нужно, чтобы воспроизведение не дёргалось.
- Загруженные изображения хранятся в памяти страницы (по `url`) до выхода к списку.
- После загрузки управление разблокируется, плеер стоит на **последнем (самом свежем)** кадре на паузе.
- Кадры, которые не удалось загрузить после повтора, пропускаются при воспроизведении, а под плеером показывается `Не удалось загрузить кадров: K`.

### 4.3. Управление воспроизведением

| Элемент | Поведение |
| :--- | :--- |
| `▶ / ⏸` | Запуск и пауза. Если стоит последний кадр и зацикливание выключено, `▶` начинает с первого кадра. |
| Ползунок | Таймлайн от первого до последнего кадра, подпись `Кадр X из N`. Перемещение не меняет состояние воспроизведения. |
| `◀` / `▶` (шаг) | Кадр назад или вперёд. |
| Скорость | `1x`, `2x`, `4x`. Базовая частота `1x` — 5 кадров в секунду (200 мс на кадр), `2x` — 10, `4x` — 20. |
| `🔁 Зациклить` | Флажок, по умолчанию выключен. Без него воспроизведение останавливается на последнем кадре. |

- Если плановый кадр один, показывается картинка, а Play, ползунок, шаги и скорость отключены; под картинкой `Пока один плановый кадр`.

### 4.4. Слой

Переключатель `[ 🖼 Оригинал ] [ 🧠 Разметка нейросети ]` (`raw_url` / `annotated_url`), позиция кадра при переключении сохраняется.
- Если картинки нужного слоя уже в памяти, переключение мгновенное.
- Если слой ещё не загружался, запускается его предзагрузка по правилам 4.2 (с индикатором и блокировкой управления). Второй слой не грузится заранее, чтобы не удваивать трафик.

### 4.5. Метаданные текущего кадра

Под картинкой всегда выводятся:

- **Дата и время съёмки** из `captured_at` (UTC в API) в **локальном времени браузера** (`toLocaleString('ru-RU')`), с пометкой `время вашего устройства`;
- **Площадь растения:** `area_display` (например, `48.3 см²` или `15430 px`); если значения нет, `площадь не определена`;
- **Номер кадра** `Кадр X из N` (и камера, если выбран селектор).

## 5. Ошибки и пустые состояния

| Ситуация | Поведение |
| :--- | :--- |
| Сервер недоступен или `5xx` при загрузке списка | `Не удалось загрузить список установок. Сервер недоступен.` + кнопка `Повторить`. |
| `404` на `frames` (установку удалили) | `Установка не найдена` + кнопка `← К списку`. |
| `frames` пуст | `Плановых кадров пока нет. Они появятся после первой автосъёмки.` |
| Ошибка загрузки отдельной картинки | Один повтор, затем пропуск кадра и счётчик из 4.2. |
| Сервер недоступен при `🔄 Обновить` | Сообщение об ошибке над плеером, уже загруженные кадры остаются. |

Другие коды (`401`, `403`, `409`, `422`, `429`, `503`, `504`) на публичных эндпоинтах не возникают; при неожиданном ответе показывается общее `Не удалось получить данные от сервера`.

---

## 6. Вне рамок MVP (план масштабирования)

- График роста площади (потребуется числовое значение площади в API, сейчас отдаётся только `area_display`);
- сравнение нескольких установок рядом;
- вход и роли в вебе (управление и скачивание видео из браузера);
- прямые ссылки на конкретную установку и кадр (`#...`);
- уменьшенные превью и ленивая подгрузка кадров для очень длинных таймлапсов;
- горячие клавиши плеера (пробел, стрелки).
