## 1. Выполненные задачи и критерии приёмки

### 1.1. Информационная панель телеметрии и отключение переключателя в Web UI (`clients/web/`)
- **Удаление переключателя mock/rpi**: из разметки `#modal-rpi-setup` полностью удалена группа радиокнопок `rpi-hw-mode`. Режим оборудования определяется исключительно процессом агента на устройстве.
- **Информационная панель read-only телеметрии**: модалка дополнена блоком `.rpi-telemetry-dashboard` с сеткой карточек телеметрии:
  - Модель платы (`#rpi-telem-board`): детальное имя из `/proc/device-tree/model` или `/sys/firmware/devicetree/base/model` (например, `Raspberry Pi 5 Model B Rev 1.0`), либо статус офлайн;
  - Режим оборудования (`#rpi-live-mode`): бейдж `Реальная плата (RPi)` или `Эмуляция (mock)` без элементов управления;
  - Статус подключения (`#rpi-live-dot`, `#rpi-live-status-text`): `Онлайн` / `Офлайн`;
  - Версии ПО (`#rpi-telem-versions`): версия Edge-агента и сервера;
  - Метрики процессора (`#rpi-telem-cpu`): загрузка CPU (%) и температура (°C);
  - Оперативная память (`#rpi-telem-ram`): использовано / всего МБ (процент);
  - Диск (`#rpi-telem-disk`): свободное место на MicroSD/SSD в ГБ;
  - Очередь кадров (`#rpi-telem-queue`): количество ожидающих пакетов в локальной офлайн-очереди;
  - Время отклика (`#rpi-live-last-ping`): дата и время последнего полученного heartbeat.
- **Генерация команды установки**: форма сохранена, по умолчанию формирует команду развертывания боевого агента (`hardware_mode: 'rpi'`).
- **Соблюдение инвариантов UI**: 0 эмодзи во всей директории `clients/web/`, 0 `window.alert` / `confirm` / `prompt`.

### 1.2. HSV-сегментация в боевом режиме без ONNX (`edge_agent/vision.py`)
- В методе `VisionPipeline.segment_plants`: при отсутствии файла `.onnx`-модели или недоступности ONNX Runtime в боевом режиме (`mock_mode=False`) реализован безопасный переход на цветовой алгоритм `_segment_plants_hsv`.
- Вместо возврата пустого списка замеров `measurements=[]` система детектирует растения по порогу HSV, формирует контуры, рассчитывает площади и возвращает размеченный кадр.
- Выводится предупреждение в журнал: `logger.warning("ONNX-модель не загружена в боевом режиме. Применяется fallback-сегментация по HSV.")`.
- Также fallback применяется в случае непредвиденных исключений во время инференса модели.

### 1.3. Автоподбор лучшего качества и умный прогрев (`edge_agent/hardware.py`)
- **Профилирование камеры**:
  - Создана структура `CameraProfile` и функция `probe_camera_capabilities(dev_path, hardware_id)`.
  - Опрос устройства через `v4l2-ctl --list-formats-ext` и `v4l2-ctl --all` с таймаутом и безопасным перехватом любых исключений.
  - Приоритет формата `MJPG` над `YUYV` для обеспечения максимального FPS и разрешения без перегрева шины USB.
  - Автоматический выбор максимального поддерживаемого разрешения (например, 1920x1080).
  - Определение поддержки автофокуса (`focus_auto`, `focus_absolute`).
  - Кэширование профилей в `HardwareManager._camera_profiles`.
- **Захват кадра в боевом режиме**:
  - Открытие через `cv2.VideoCapture(real_dev_path, cv2.CAP_V4L2)`.
  - Установка `CAP_PROP_BUFFERSIZE = 1` для исключения отдачи устаревших кадров из кольцевого буфера V4L2.
  - Установка `CAP_PROP_FOURCC` (`MJPG` / `YUYV`), `FRAME_WIDTH`, `FRAME_HEIGHT`.
  - До 3 повторов при ошибках открытия видеоустройства с задержкой 0.3 с.
- **Умный прогрев по стабилизации яркости**:
  - Базовая пауза 0.5–1.0 с после переключения реле света/вспышки в `capture_frame_with_sequence`.
  - Цикл чтения кадров до стабилизации яркости (`|luma(t) - luma(t-1)| < 1.5` на 2 кадрах подряд) с общим таймаутом 3.5 с.
  - Логирование параметров съемки в формате `[SNAP]` (камера, разрешение, кодек, прогревочные кадры, изменение luma, затраченное время).
- **Проверка офлайн-очереди**: в `edge_agent/offline_queue.py` проверено отсутствие жестких искусственных лимитов на вместимость локальной очереди.

### 1.4. Автокалибровка и карточка камеры в Telegram-боте (`edge_agent/`, `server/`, `clients/telegram_bot/`)
- **Команда `AUTOCALIBRATE_CAMERA`**:
  - Добавлена обработка в `EdgeOrchestrator` (`_handle_autocalibrate_camera`).
  - Опрашивает возможности камеры, инвалидирует кэш профиля, определяет параметры и возвращает форматированную сводку в `CommandResult`.
- **Серверный эндпоинт `POST /api/cameras/{camera_id}/autocalibrate`**:
  - Доступен роли `developer`.
  - Проверяет доступность RPi (503 при офлайне), ставит команду в очередь и ожидает завершения до 10 с.
  - Сохраняет профиль в `SystemSetting` (`key=f"camera_profile_{hardware_id}"`).
  - Включает `calibration_summary` в выдачу `GET /api/cameras` и `serialize_camera`.
- **Telegram-бот**:
  - В карточке камеры (`cam:view:<id>`) отображается профиль качества (при наличии) и добавлена кнопка `⚙️ Автокалибровка`.
  - Обработчик `cam:calibrate:<id>` запускает автокалибровку и выводит подробную сводку пользователю.
  - При привязке камеры к установке (`cam:do_bind:<cam>:<inst>`) автоматически запускается автоподбор параметров и прикрепляется к сообщению об успешной привязке.
