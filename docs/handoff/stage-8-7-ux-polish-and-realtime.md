# Handoff: Этап 8.7 (UX-полировка, безопасная авторизация, галерея, адаптивные заглушки и real-time мониторинг)

- **Ветка**: `stage-8/ux-polish-and-realtime`
- **Режим**: FULL
- **Цель**: Исправить дефекты по итогам живого тестирования v0.6.1: обязательное подтверждение кодом из Telegram при регистрации в вебе, рекомендованное редактируемое имя из ТГ, реальные кадры в галерее с расчётом длительности таймлапса (~15 fps), мягкая классифицированная обработка ошибок без лишних showError/showConfirm, случайные тематические SVG-заглушки и весёлые фразы загрузки, строгое автоопределение Raspberry Pi / Mock, рамочный баннер сети, прижатый к низу футер и фоновый поллинг каждые 5 с.

---

## 1. Выполненные изменения

### 1. Регистрация и вход Web ↔ Telegram
- **`server/api/auth.py`**:
  - В `auth_web_login`: незарегистрированный пользователь (`User` отсутствует в БД) больше автоматически не создаётся и не логинится. Сервер возвращает `HTTP 403` с `detail="telegram_verification_required"`.
  - При повторном входе существующего пользователя существующий `user.login` не перезаписывается без необходимости.
  - В `auth_web_register_start`: из `TelegramContact` извлекается и возвращается `recommended_name`.
  - В `auth_web_register_complete`: поле `password` сделано опциональным (`password: str | None = None`).
  - В `auth_web_me` и `server/api/system.py:get_version`: возвращается `bot_username: str | None`.
- **`clients/web/js/auth.js`**:
  - При получении 403 `telegram_verification_required` форма входа автоматически переключается на модалку регистрации с предзаполненным Telegram и пояснением о необходимости подтверждения через бота.
  - На шаге 3 поле имени предзаполняется `recommended_name` с подсказкой «Рекомендуемое имя из Telegram (можно изменить)».
  - В `#modal-login` и `#modal-register` громоздкие описания заменены на кликабельную ссылку на Telegram-бота `https://t.me/<BOT_USERNAME>`.
  - Все ошибки валидации и сетевые сообщения выводятся инлайн красным текстом под полями (`#login-form-error`, `#reg-error-step1`, `#reg-error-step2`, `#reg-error-step3`) без спама модалками `showError`.

### 2. Реальные кадры в Галерее и расчёт длительности таймлапса
- **`clients/web/js/gallery.js`**:
  - В область отображения кадра монтируется реальный элемент `<img>` с URL кадра из API и обработчиком `onerror`, который при ошибке декодирования переключает область на заглушку повреждённого кадра (Категория D).
  - В блоке управления экспортом добавлено числовое поле ввода длительности `id="gallery-duration-input"` (`min="1"`, `step="1"`).
  - При открытии галереи и смене камеры автоматически вычисляется рекомендованная длительность: `Math.max(1, Math.round(framesCount / 15))` (~15 fps).
  - В реальном времени рядом отображается бейдж итогового FPS и контекстные предупреждения:
    - если `fps > 30` — предупреждение о прореживании до 30 fps;
    - если `durationSec > framesCount` (< 1 fps) — подсказка об удержании кадра;
    - если `< 1` или нецелое — инлайн-ошибка и блокировка скачивания.

### 3. Классифицированная мягкая обработка исключений
- `showError` сохранён в `dialogs.js` исключительно как страховочный перехватчик для необработанных исключений (500 и ошибки JS).
- Обрыв сети (TypeError, fetch failed, 502–504): активирует рамочный баннер `#server-offline-banner`. Модальные окна галереи и тестового снимка не закрываются, внутри них отображается заглушка Категории C с заблокированными кнопками.
- Пустая галерея (0 кадров) и офлайн-плата: модалка не закрывается с ошибкой, отображается заглушка Категории A или B.
- Подтверждение выхода: `showConfirm` в `app.js` удалён. В шапке приложения интегрирован компактный инлайн-блок `#header-logout-confirm` («Выйти? Для повторного входа потребуется код. [Да] [Отмена]»).

### 4. Тематические SVG-заглушки и весёлая загрузка
- Создан модуль `clients/web/js/placeholders.js`:
  - Категория A (0 кадров): «Растение застеснялось. Фотографий нет», «Похоже, фотограф забыл снять крышку с объектива», «Здесь ничего нет — или просто кто-то прошёлся по клавиатуре и стёр базу».
  - Категория B (Камера / RPi недоступна): «Картинки не будет — фотограф сбежал», «Камера ушла на перерыв. Проверьте подключение платы».
  - Категория C (Обрыв связи): «Возможно, кто-то перегрыз провод», «Связь с сервером временно оборвалась».
  - Категория D (Битый кадр): «Кадр потерялся по дороге с грядки».
  - Функция `getPlaceholderHTML(category)` со случайным выбором (`Math.random()`).
  - Функция `getRandomLoadingPhrase()` со случайными фразами для съёмки ростка.
  - Единый серый стиль текста `#94a3b8`, `max-width: 280px`, `text-align: center`. 0 Unicode-эмодзи.

### 5. Автоопределение RPi / Mock и честный статус
- **`edge_agent/config.py`**:
  - `is_raspberry_pi()` проверяет одновременно два условия: `/proc/device-tree/model` существует и содержит `"Raspberry Pi"` И библиотека `gpiozero` доступна (`importlib.util.find_spec("gpiozero") is not None`).
- **`server/core/system_status.py`**:
  - Онлайн-статус платы ограничен таймаутом `diff_sec <= 35.0` секунд.
- **`server/api/edge.py`**:
  - Heartbeat сохраняет в `system_settings.rpi_last_telemetry` фактический режим `hardware_mode` (`"rpi"` или `"mock"`).
- **`clients/web/js/rpi_setup.js`**:
  - При отсутствии телеметрии или офлайне отображается `'Режим: Не подключено'`. При эмуляторе — `'Режим: Эмулятор (mock)'`.
  - Радио-кнопка боевого режима `rpi` блокируется (`disabled`), если плата офлайн или реальное железо не обнаружено. Ошибки формы выводятся в `#rpi-setup-error` без `showError`.

### 6. Вёрстка баннера, футер и фоновый поллинг
- **`clients/web/index.html`**:
  - `#server-offline-banner` перенесён из подвала в поток документа сразу под `<header>` перед контентом.
- **`clients/web/style.css`**:
  - `#server-offline-banner`: тёмный фон `rgba(24, 15, 20, 0.95)`, рамка `1px solid #ef4444`, красный текст, тень.
  - `html, body { min-height: 100vh; display: flex; flex-direction: column; }`, `.app-main { flex: 1; }`, `.app-footer { margin-top: auto; }` — футер гарантированно прижат к низу страницы.
- **`clients/web/js/app.js`**:
  - Реализован фоновый поллинг `startBackgroundPolling()` каждые 5 секунд (с проверкой `document.hidden`), опрашивающий статус сессии (`/api/auth/web/me`) и актуальный список установок.
