# Задача QA: Этап 5 — Приёмочное тестирование CLI-клиента

- **Этап**: 5 (CLI-клиент)
- **Режим**: FULL
- **Ветка**: `stage-5/cli`
- **Компонент**: `cli`
- **Allowed Paths**: `tests/e2e/`, `docs/qa_log.md`

## Прочитать перед началом
1. `docs/PROJECT.md`, включая **раздел 9 («Правила скорости и тестов»)** — обязателен для Builder и QA!
   - Быстрые тесты (<3 с на тест, <60 с весь набор).
   - Подготовка состояния через публичные эндпоинты (RPi онлайн только через `POST /api/edge/heartbeat`).
   - Использование общих фикстур из `tests/e2e/conftest.py` (поднятие тестового сервера FastAPI uvicorn на свободном порту с изолированной БД и media dir, эмуляция RPi через edge-эндпоинты).
   - Запуск через `timeout 300 ... pytest`.
   - Не более 2 неудачных попыток подряд (при блоке — статус `BLOCKED`).
2. `docs/CLI_SPEC.md` — команды, права ролей, обработка ошибок.
3. `docs/handoff/cli.md` — отчёт Builder-а о реализации.

## Сценарии и критерии приёмки
1. Проверка справки: `python -m clients.cli.main help` и `<раздел> info` для всех 6 разделов (`auth`, `unit`, `camera`, `light`, `snap`, `system`) возвращают 0 и содержат примеры команд.
2. Проверка изоляции импортов: `grep -rn "from server\|from shared\|from edge_agent\|import server\|import shared" clients/cli` возвращает пустой вывод.
3. Сквозной сценарий e2e (в `tests/e2e/test_cli_e2e.py`):
   - Запуск изолированного тестового сервера FastAPI с тестовой БД SQLite и временным каталогом media.
   - Эмуляция RPi: отправка heartbeat, регистрация установки и камеры.
   - Выполнение CLI через subprocess (с изолированным тестовым `.env` и временным файлом сессии `HOME=tmp_path`):
     - `auth login` с паролем Developer.
     - `unit list` (проверка колонок).
     - `camera list` / `camera scan`.
     - `snap take 1` (с эмуляцией выполнения команды mock RPi-агентом через edge polling) и проверка вывода.
     - `snap video 1` (сборка таймлапса через реальный ffmpeg с проверкой создания файла).
     - Проверка обработки 1 кадра в `snap video` (сохранение `.jpg`).
4. Негативные сценарии:
   - Неверный пароль при `auth login` → понятный вывод ошибки без трейсбека, код 1.
   - Запрос операции Developer под Гостем/Biologist → сообщение о недостаточных правах (403), код 1.
   - Сервер недоступен (неверный порт) → понятное сообщение о недоступности сервера по разделу 4 `CLI_SPEC.md`, код 1.
   - Неверный `target` установки → сообщение об ошибке, код 1.
5. Запуск полного набора тестов:
   - `clients/cli/.venv/bin/pytest clients/cli/tests -q`
   - `server/.venv/bin/pytest server/tests -q`
   - `server/.venv/bin/pytest tests/e2e -q`
6. Линтер и форматирование: `ruff check .` и `ruff format --check .` проходят чисто.

По итогам проверки сделай запись в `docs/qa_log.md` и опубликуй вердикт (`PASS` или `FAIL` с дефектами) на доске сообщений.
