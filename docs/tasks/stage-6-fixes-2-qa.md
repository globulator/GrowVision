## Критерии и сценарии проверки
1. **Реле при Heartbeat**:
   - `perform_heartbeat` инициализирует реле (свет ВКЛ, вспышка ВЫКЛ) только для новых, ещё не инициализированных установок;
   - Два вызова `perform_heartbeat` подряд не переключают пины уже инициализированной установки;
   - Если пользователь выключил свет (`LIGHT_MAIN off`), следующий heartbeat не включает его обратно;
   - При занятом аппаратном мьютексе (идёт съёмка) `perform_heartbeat` не блокируется и не меняет состояние пинов.
2. **Возврат пинов после `RELAY_TEST`**:
   - `RELAY_TEST` возвращает пины в исходное состояние (включённый свет остаётся включённым после теста);
   - Проверен метод `hardware.get_pin_state(pin) -> bool`.
3. **Резолв путей и документация**:
   - Относительные `MODEL_PATH` и `OFFLINE_QUEUE_DIR` корректно резолвятся относительно корня репозитория;
   - Единый путь `edge_agent/models/lettuce_seg_v1.onnx` в `.env.example`, `config.py` и `DEPLOYMENT_RPI.md`;
   - В `docs/DEPLOYMENT_RPI.md` строка `<OWNER>` заменена на «ваш аккаунт GitHub».
4. **Тесты**:
   - Все unit-тесты `edge_agent/tests/` проходят быстро (<3с);
   - Регрессионный набор тестов проходит чисто (`clients/cli/tests`, `server/tests`, `tests/e2e`);
   - `ruff check .` и `ruff format --check .` проходят без замечаний.
