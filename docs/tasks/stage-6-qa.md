## Сценарии и критерии приёмки
1. **Unit-тесты компонента**:
   - `timeout 300 ./edge_agent/.venv/bin/pytest edge_agent/tests -q` — все 31 тест проходят за доли секунды.
2. **Проверка изоляции**:
   - `grep -rn --include="*.py" "from server\|from clients\|import server\|import clients" edge_agent` возвращает пустой вывод.
3. **Сквозные сценарии e2e (в `tests/e2e/test_edge_e2e.py`)**:
   - Поднятие реального тестового сервера FastAPI uvicorn на свободном порту с изолированной SQLite БД и директорией media (через фикстуры `test_server_url` / `e2e_server`).
   - Запуск реального Edge-агента в mock-режиме (`HARDWARE_MODE=mock`) против этого сервера (через фоновый поток/подпроцесс с таймаутом).
   - **Сценарий 1 (Heartbeat и телеметрия)**:
     - Агент отправляет Heartbeat на сервер.
     - Сервер переводит RPi в статус `online` (проверяется через `GET /api/system/status`), телеметрия железа и ПО отображается корректно.
   - **Сценарий 2 (Команды управления и сканирование)**:
     - `POST /api/cameras/scan` -> сервер ставит команду `SCAN_CAMERAS`, агент забирает её через claim и возвращает найденные камеры, сервер регистрирует камеры (`GET /api/cameras`).
     - `POST /api/control/light/main` и `POST /api/control/relay-test` -> агент выполняет команды и возвращает статус `done`.
   - **Сценарий 3 (Ручной снимок SNAP)**:
     - `POST /api/control/snap` -> агент захватывает кадр, выполняет детекцию ArUco и сегментацию ONNX, загружает кадр (`POST /api/edge/captures`) с `command_id`, затем отправляет `result`. Сервер связывает кадр и возвращает клиенту замеры и URL файлов.
   - **Сценарий 4 (Офлайн-очередь и доотправка)**:
     - При недоступности сервера (например, временная остановка или неверный URL) агент сохраняет кадр в `offline_queue/`.
     - При восстановлении связи агент в цикле выгружает накопленный кадр (`POST /api/edge/captures`), кадр успешно сохраняется в БД сервера, а файл в очереди удаляется.
     - Проверка изоляции битых пакетов (422/404): переносятся в `offline_queue/failed/`.
4. **Проверка документации**:
   - `docs/DEPLOYMENT_RPI.md` и `docs/HARDWARE_WIRING.md` созданы, описывают развёртывание на Raspberry Pi 5 и схему подключения.
5. **Регрессионный набор тестов**:
   - `clients/cli/.venv/bin/pytest clients/cli/tests -q` (40 тестов)
   - `server/.venv/bin/pytest server/tests -q` (89 тестов)
   - `server/.venv/bin/pytest tests/e2e -q` (все e2e тесты)
6. **Линтер и форматирование**:
   - `ruff check .` и `ruff format --check .` проходят чисто.

По итогам проверки сделай запись в `docs/qa_log.md` и опубликуй вердикт (`PASS` или `FAIL` с дефектами) на доске сообщений.
