## Критерии приёмки

1. **Тестовый интервал съёмки `TEST_CAPTURE_INTERVAL_SEC`**:
   - Необязательная целочисленная переменная окружения (минимум 10 секунд). При значении < 10 агент падает с ошибкой валидации при старте.
   - Если задана: плановая съёмка запускается каждые N секунд от момента запуска агента (вместо сетки по часам и вместо серверного интервала).
   - Работает одинаково и в `HARDWARE_MODE=rpi`, и в `HARDWARE_MODE=mock`.
   - При старте логируется явный `WARNING: ТЕСТОВЫЙ ИНТЕРВАЛ СЪЁМКИ: N с`.
   - Факт использования тестового интервала обязательно попадает в `debug_log_line` каждой плановой съёмки.
   - Если переменная не задана (или пустая): строго прежнее поведение (астрономическая сетка UTC по часам `HH % interval == 0 and MM == 0`).

2. **Команда симуляции и посева истории кадров `python -m edge_agent.simulator seed`**:
   - Сигнатура:
     ```bash
     python -m edge_agent.simulator seed --installation <id> [--frames 48] [--step-hours 1] [--start <UTC>] [--cameras all|<hardware_id,...>] [--from-dir <папка>]
     ```
   - Загружает через настоящий Edge API (`POST /api/edge/captures`, с заголовком `X-Edge-Key` и адресом `SERVER_URL` из `edge_agent/.env` или окружения) серию плановых кадров с прошлыми временными метками `captured_at`.
   - Без `--from-dir`: кадры синтетические (OpenCV) — нейтральный фон, зелёное растение с ростом площади по номеру кадра, маркер ArUco `DICT_4X4_50` id 0 известного размера в пикселях, разные ракурсы/смещения по камерам.
   - С `--from-dir`: берутся JPEG из указанной папки по порядку имён файлов (по кругу при нехватке).
   - `annotated_image` при посеве равен исходному (`raw_image`).
   - `area_px` рассчитывается зелёным порогом в цветовом пространстве HSV.
   - `aruco_area_px` рассчитывается настоящей детекцией `cv2.aruco`.
   - Повторный запуск безопасен (сервер возвращает 200 на дубли по уникальному ключу `(installation_id, camera_id, captured_at)`).
   - Валидация камер: камеры должны быть уже зарегистрированы (`scan`) и привязаны к установке; если камера не найдена/не привязана — выводится понятная ошибка с подсказкой.

3. **Синтетика в mock-режиме и строгий запрет в rpi-режиме**:
   - В mock-режиме кадры размером 1280x720 генерируются тем же генератором синтетики (зелёное растение + ArUco маркер `DICT_4X4_50` id 0).
   - Если OpenCV не установлен: запасной 1x1 JPEG с обязательным логированием `WARNING`.
   - Режим `HARDWARE_MODE=rpi` **не использует синтетику ни при каких условиях**: при отсутствии камеры или сбое камеры — ошибка, никакой синтетики (верифицируется unit-тестом).
   - Константы `1200` и `5400` в mock-ветках `VisionPipeline` заменить на настоящую детекцию ArUco (`cv2.aruco`) и сегментацию по порогу HSV.

4. **Документация в `docs/USER_GUIDE.md`**:
   - Добавить раздел «Тестирование без ожидания»:
     - (а) Запуск без реального оборудования (сервер, агент в mock-режиме, CLI);
     - (б) `TEST_CAPTURE_INTERVAL_SEC` для тестирования с реальными камерами на Raspberry Pi (например: 30 с, сбор 20 кадров, последующая сборка видео через `snap video`);
     - (в) Команда `seed` синтетикой и из каталога со снимками (`--from-dir`).

5. **Тесты**:
   - **Unit-тесты (`edge_agent/tests/`)**:
     - Генератор синтетических кадров: маркер ArUco находится, площадь растения строго монотонно растёт с ростом номера кадра;
     - HSV-сегментация: корректный подсчёт зелёных пикселей;
     - Итератор `--from-dir`: циклическое чтение JPEG-файлов;
     - Валидация интервала: `TEST_CAPTURE_INTERVAL_SEC < 10` отклоняется при инициализации конфигурации;
     - Режим `rpi`: синтетический генератор недоступен/заблокирован.
   - **E2E-тесты (`tests/e2e/test_edge_test_tools_e2e.py`)**:
     - Посев 6 кадров на 2 камеры через `simulator seed`: `GET /api/timelapse/{id}/frames` возвращает 12 кадров, видео успешно собирается по `camera_id`, `area_display` отображается в см² при заданном `aruco_size_mm`;
     - Агент в mock-режиме с `TEST_CAPTURE_INTERVAL_SEC=10` корректно отправляет плановые кадры на сервер (время подменяется через mock/monkeypatch, без реального `time.sleep`).

6. **Быстродействие и чистота репозитория**:
   - Все правила раздела 9 `PROJECT.md` (fast tests, <3с на тест, общий прогон <60с, никаких `growvision.db*` в корне).
