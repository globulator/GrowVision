- **Компонент**: `edge`

## Цель проверки
Провести независимое тестирование и верификацию тестовых инструментов Edge-агента: ускоренного интервала съёмки `TEST_CAPTURE_INTERVAL_SEC`, симулятора посева истории кадров `edge_agent.simulator seed`, генератора синтетических кадров в mock-режиме, строгого запрета синтетики в rpi-режиме, документации и соблюдения правил быстрого тестирования `PROJECT.md` (раздел 9).

---

## Проверочный лист (Acceptance Criteria)

### 1. Тестовый интервал плановой съёмки `TEST_CAPTURE_INTERVAL_SEC`
- Переменная `TEST_CAPTURE_INTERVAL_SEC`: валидация `>= 10` с. При значении `< 10` с — агент завершается с ошибкой конфигурации.
- При наличии переменной: плановая автосъёмка запускается циклически каждые N секунд от момента запуска оркестратора (вместо сетки по часам UTC).
- Работает и в режиме `HARDWARE_MODE=rpi`, и в `HARDWARE_MODE=mock`.
- При старте в логах фиксируется `WARNING` вида: «ТЕСТОВЫЙ ИНТЕРВАЛ СЪЁМКИ: N с».
- Факт использования тестового интервала фиксируется в `debug_log_line` каждой плановой съёмки (`[TEST_INTERVAL=N s] ...`).
- Без переменной: строго сохраняется исходное поведение астрономической сетки UTC по часам (`HH % n_hours == 0 and MM == 0`).

### 2. Симулятор и посев истории кадров `python -m edge_agent.simulator seed`
- Команда:
  ```bash
  python -m edge_agent.simulator seed --installation <id> [--frames 48] [--step-hours 1] [--start <UTC>] [--cameras all|<hardware_id,...>] [--from-dir <папка>]
  ```
- Загружает кадры через настоящий Edge API (`POST /api/edge/captures`, с заголовком `X-Edge-Key` и адресом `SERVER_URL` из `.env` или окружения) с прошлыми метками времени `captured_at`.
- Без `--from-dir`: кадры синтетические 1280x720 через OpenCV (растущее зелёное растение с ростом площади по номеру кадра, маркер ArUco `DICT_4X4_50` id 0, различные ракурсы по камерам).
- С `--from-dir`: чтение реальных JPEG-файлов из папки по кругу.
- `annotated_image` при посеве равен исходному `raw_image`.
- `area_px` рассчитывается порогом в цветовом пространстве HSV.
- `aruco_area_px` рассчитывается настоящей детекцией `cv2.aruco`.
- Повторный запуск безопасен: существующие дубликаты возвращают 200 с сохранением `capture_id`.
- Камеры должны быть зарегистрированы и привязаны к установке; если камера не найдена или не привязана — выводится понятная ошибка с подсказкой.

### 3. Синтетика в mock-режиме и строгий запрет в rpi-режиме
- В mock-режиме кадры 1280x720 синтетические (тот же генератор). Если OpenCV отсутствует — 1x1 JPEG с `WARNING` в лог.
- Режим `rpi` **не использует синтетику ни при каких условиях**: при отсутствии или сбое камеры возникает ошибка, никакой синтетики не подставляется.
- Константы `1200` и `5400` в mock-ветках `VisionPipeline` заменены на реальную детекцию ArUco и HSV-сегментацию.

### 4. Документация в `docs/USER_GUIDE.md`
- Проверить наличие и полноту раздела 7 «Тестирование без ожидания»:
  - Запуск без железа (сервер, агент mock, CLI);
  - `TEST_CAPTURE_INTERVAL_SEC` для реальных камер на Raspberry Pi;
  - `seed` синтетикой и из каталога снимков (`--from-dir`).

### 5. Быстродействие, чистота репозитория и раздел 9 `PROJECT.md`
- Тесты быстрые: unit и e2e тесты выполняются без реального `sleep` (<3 с на тест).
- Общий тестовый прогон репозитория < 60 секунд.
- Тесты не оставляют файлов `growvision.db*` в корне проекта или рабочих директориях.
- `git status --short` пуст после прогона тестов.
- Линтер `ruff check .` и `ruff format --check .` проходят без замечаний.
- `VERSION` не изменялся (`0.3.1`), теги не ставились.
