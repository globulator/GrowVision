## Критерии приёмки

1. **Профиль пользователя (`/profile` или кнопка «👤 Профиль»)**:
   - Поля `login`, `authorized_at`, `last_active_at` берутся из ответа `GET /api/auth/me`.
   - Прочерк «—» отображается **только если поля реально пусты/null**, но не при наличии валидного значения даты/строки.

2. **Отображение всех полей карточки установки**:
   - Все поля читаются строго по фактическим ключам ответа `GET /api/installations/{id}` (сверить с `API_CONTRACT.md` разд. 4.2): `culture_name`, `aruco_size_mm`, `last_area_display`, `light_gpio_pin`, `flash_gpio_pin`, `is_archived`, `created_at`, `updated_at`, `camera_count` и др.
   - Исправление должно быть консистентным везде: список установок, карточка, сообщение после создания установки, сообщение после редактирования, архивирование/разархивирование.
   - После изменения размера ArUco через меню редактирования обновленная карточка показывает новое значение (например, `50.0 мм`).

3. **Корректный `user_id` в inline-коллбэках**:
   - В обработчиках inline-кнопок `user_id` должен извлекаться из `callback.from_user.id` (поскольку `callback.message.from_user` в Telegram — это сам бот).
   - `user_id` передается явным отдельным параметром в вызовы логики и `api_client` (включая `handlers/system.py` около строки 148 и `handlers/installations.py` около строки 341).
   - Контроль: `grep -rn "target_msg\.from_user" clients/telegram_bot/handlers/` не должен находить обращений к `from_user` сообщения как источнику ID пользователя.

4. **Системные команды бота (`set_my_commands`)**:
   - При старте бота вызывается `bot.set_my_commands(...)` со списком актуальных команд:
     - `/start` — Главное меню
     - `/help` — Справка
     - `/version` — Версия системы
     - `/login` — Вход в систему
     - `/cancel` — Отмена текущего действия
   - Устаревшие команды (`/systems`, `/info`, `/cameras`) удаляются из меню клиента Telegram.

5. **Обработка неизвестных сообщений**:
   - Если пользователь отправляет произвольный текст вне активного режима ввода (FSM-состояния), бот отвечает:
     `Не понял. Список команд: /help`

6. **Заметки о багах через префикс `*`**:
   - Любое сообщение пользователя, начинающееся с символа `*` (например: `*не работает кнопка`), считается баг-репортом / заметкой о дефекте.
   - Заметка записывается в журнал вместе с контекстом последних 20 зафиксированных событий бота (кольцевой буфер событий).
   - Пользователю отправляется ответ: `Записано: BUG-LOG-N` (где N — порядковый номер).
   - Если пользователь находился в процессе ввода в FSM-сценарии (например, шаг создания установки), **сценарий не прерывается и не сбрасывается**, FSM остаётся на текущем шаге.

7. **Журналирование событий `BOT_DEBUG_LOG` и утилита `bug_log`**:
   - Переменная окружения `BOT_DEBUG_LOG=true` включает запись структурированного JSONL-журнала в `clients/telegram_bot/logs/` (каталог добавлен в `.gitignore`).
   - Журнал фиксирует: входящие сообщения, нажатия inline-кнопок, переходы состояний FSM, исходящие ответы бота, вызовы Client API, ошибки.
   - Пароли пользователей и API-ключи гарантированно маскируются.
   - Срок хранения логов: до 7 дней.
   - Реализована CLI-утилита:
     `python -m clients.telegram_bot.tools.bug_log list` — список баг-заметок;
     `python -m clients.telegram_bot.tools.bug_log show <N>` — подробный контекст заметки N (включая предшествующие события);
     `python -m clients.telegram_bot.tools.bug_log tail` — вывод последних событий журнала.

8. **Поддержка `TELEGRAM_PROXY`**:
   - Необязательная переменная окружения `TELEGRAM_PROXY` в `.env` бота (пусто — прямое подключение без прокси).
   - Поддерживаются протоколы `http://` и `socks5://` (при необходимости добавить зависимость в `requirements.txt`, например `aiohttp-socks`).
   - При сбое подключения к Telegram API выполняется повтор с паузой и понятная запись ошибки в лог.
   - Обновить `clients/telegram_bot/.env.example` и раздел 1.1 в `docs/BOT_SPEC.md`.

9. **Проверка уникальности имени установки на шаге 1 мастера**:
   - На шаге 1 ввода имени установки выполняется немедленный запрос `GET /api/installations?include_archived=true`.
   - Если имя уже занято активной или архивной установкой, бот сообщает об этом и просит ввести другое имя, **не сбрасывая сценарий создания**.
   - Обработка ошибки 409 от сервера на финальном этапе создания сохраняется как страховочная защита.

10. **Размер ArUco по умолчанию 50 мм в мастере создания**:
    - На шаге 5 мастера в подсказке указывается «по умолчанию 50 мм».
    - При нажатии инлайн-кнопки «Пропустить» отправляется `aruco_size_mm=50.0`.
    - Контракт Client API сервера остаётся без изменений.

11. **Фейковый Telegram Bot API и E2E тесты**:
    - В `tests/e2e/fake_telegram.py` реализован легковесный HTTP-сервер фейкового Telegram Bot API (на базе `aiohttp`), в котором `callback.message.from_user` — это бот (эмуляция реального поведения Telegram Bot API).
    - В `tests/e2e/test_bot_fixes_round2_e2e.py` покрыть сценарии:
      - Вход в систему и просмотр профиля с реальными датами;
      - Создание установки с проверкой занятого имени (дубль имени отклоняется на шаге 1), ArUco 50 мм по умолчанию, отображение карточки со всеми полями;
      - Нажатие кнопок меню «Система» и «Установки» (регрессионная проверка `callback.from_user.id`);
      - Ответ на неизвестный текст («Не понял. Список команд: /help»);
      - Баг-заметка через `*` без сброса FSM (с ответом `Записано: BUG-LOG-N`).

12. **Быстродействие и чистота репозитория (раздел 9 `PROJECT.md`)**:
    - Тесты быстрые (<3с на тест, общий прогон <60с, реальных `sleep` нет).
    - Файлы `growvision.db*` в корне не создаются.
    - `git status --short` пуст после запуска тестов.
    - Линтер и форматирование: `ruff check .` и `ruff format --check .` чистые.
    - Формат коммитов: `тип(scope): описание`, scope обязателен (`bot`, `test`, `docs`).
    - Версию в `VERSION` не менять (`0.3.1`), теги не ставить.
