- **Компонент**: `telegram_bot`
- **Ветка**: `stage-7/bot-fixes-2`
- **Режим**: FULL
- **Спецификация API**: `docs/API_CONTRACT.md` (раздел 4: Client API)
- **Спецификация бота**: `docs/BOT_SPEC.md`
- **Правила тестирования**: `docs/PROJECT.md` (раздел 9: правила скорости и тестов)
- **Отчёт реализации**: `docs/handoff/bot.md`

## Цель проверки
Провести независимое тестирование и верификацию доработок Telegram-бота раунда 2: корректности отображения профиля и карточек установок, передачи `user_id` из `callback.from_user.id`, работы команд `set_my_commands`, ответов на неизвестные сообщения, баг-заметок `*` с JSONL-журналом и утилитой `bug_log`, поддержки `TELEGRAM_PROXY`, проверки занятого имени на шаге 1 и дефолтного ArUco 50 мм, а также сквозных e2e-тестов с фейковым Bot API (`tests/e2e/fake_telegram.py`).

---

## Проверочный лист (Acceptance Criteria)

1. **Профиль**:
   - `login`, `authorized_at`, `last_active_at` берутся из `GET /api/auth/me`.
   - Символ «—» отображается исключительно если поле реально пустое/null.

2. **Карточка установки**:
   - Все поля читаются по реальным ключам ответа `GET /api/installations/{id}` (`culture_name`, `aruco_size_mm`, `last_area_display`, `light_gpio_pin`, `flash_gpio_pin`, `is_archived`, `created_at`, `updated_at`, `camera_count` и др.).
   - Исправление консистентно во всех местах: список, карточка, после создания, после редактирования, архив.
   - После изменения размера ArUco обновленная карточка показывает новое значение (например, `50.0 мм`).

3. **`user_id` в inline-коллбэках**:
   - В обработчиках inline-кнопок `user_id` извлекается строго из `callback.from_user.id` и передается отдельным параметром (включая `handlers/system.py:148` и `handlers/installations.py:341`).
   - Проверка: `grep -rn "target_msg\.from_user" clients/telegram_bot/handlers/` дает 0 совпадений.

4. **Системные команды бота**:
   - При старте бот вызывает `set_my_commands`: `/start`, `/help`, `/version`, `/login`, `/cancel`.
   - Устаревшие команды (`/systems`, `/info`, `/cameras`) отсутствуют в меню.

5. **Неизвестные сообщения**:
   - При отправке текста вне режима ввода (FSM) бот отвечает: `Не понял. Список команд: /help`.

6. **Баг-заметки на `*`**:
   - Сообщение, начинающееся с `*`, сохраняется в журнал с последними 20 событиями.
   - Бот отвечает: `Записано: BUG-LOG-N`.
   - В режиме ввода FSM (например, шаги создания установки) сценарий не прерывается и не сбрасывается.

7. **Журналирование `BOT_DEBUG_LOG` и утилита `bug_log`**:
   - `BOT_DEBUG_LOG=true` включает JSONL-журнал в `clients/telegram_bot/logs/` (папка в `.gitignore`).
   - Пароли и API-ключи маскируются.
   - Срок хранения логов — до 7 дней.
   - Утилита `python -m clients.telegram_bot.tools.bug_log` поддерживает подкоманды `list`, `show <N>`, `tail`.

8. **Поддержка `TELEGRAM_PROXY`**:
   - Переменная `TELEGRAM_PROXY` в `.env` (http://, socks5://).
   - Повторы при сбоях сети с паузой и логированием.
   - Документировано в `.env.example` и `docs/BOT_SPEC.md` п. 1.1.

9. **Мастер создания установки**:
   - Имя проверяется сразу после шага 1 через `GET /api/installations?include_archived=true`.
   - При занятом имени бот запрашивает другое имя без сброса FSM.
   - Обработка 409 на финальном шаге сохранена.

10. **ArUco 50 мм по умолчанию**:
    - На шаге 5 мастера есть подсказка «по умолчанию 50 мм».
    - Кнопка «Пропустить» отправляет `aruco_size_mm=50.0`.

11. **E2E тесты с фейковым Bot API**:
    - `tests/e2e/fake_telegram.py` эмулирует Telegram API (`callback.message.from_user` — бот).
    - Все сценарии в `tests/e2e/test_bot_fixes_round2_e2e.py` успешно проходят.

12. **Быстродействие и чистота репозитория (раздел 9 `PROJECT.md`)**:
    - Быстрые тесты (<3 с на тест, общий сьют <60 с).
    - `git status --short` пуст, `growvision.db*` в корне отсутствуют.
    - Линтер `ruff check .` и `ruff format --check .` чистые.
    - `VERSION` сохранен без изменений (`0.3.1`).
