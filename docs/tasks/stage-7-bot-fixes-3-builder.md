## Критерии приёмки

1. **Кнопка «Пропустить» на шаге ArUco в мастере создания установки**:
   - Кнопка «Пропустить» отправляет `aruco_size_mm = null` (значение не задано, расчет площади в пикселях px), а не 50.0.
   - Подсказка «по умолчанию 50 мм» убрана из текста шага 5.
   - Ввод положительного числа (`> 0`) работает как раньше, задавая размер маркера в мм.
   - Тест: создание установки через нажатие кнопки «Пропустить» формирует карточку установки со значением ArUco: `не задан`.

2. **Отказоустойчивое подключение при старте бота**:
   - При ошибке связи с Telegram API (`api.telegram.org`) на этапе старта бот **не падает и не завершает процесс**.
   - Выполняются повторные попытки подключения со ступенчатой паузой: `5, 10, 20, 40`, а далее каждые `60` секунд.
   - В лог выводится понятное сообщение:
     `Нет доступа к api.telegram.org: проверьте VPN или TELEGRAM_PROXY`
   - Процесс продолжается до успешного подключения либо до получения сигнала прерывания (Ctrl+C / SIGINT / SIGTERM).

3. **Самовосстановление при сетевом сбое во время long polling**:
   - При сетевых сбоях (обрыв VPN-туннеля, отказ DNS, таймаут шлюза) в цикле polling бот автоматически переподключается с использованием той же схемы пауз (`5, 10, 20, 40, 60...` с) без падения процесса.
   - Сигнал остановки (Ctrl+C) корректно завершает работу бота без зависания.
   - E2E/интеграционный тест: фейковый сервер Telegram API становится временно недоступным на несколько секунд (время подменяется через mock/monkeypatch без реального сна), после восстановления доступности бот успешно продолжает обработку команд и отвечает на `/start`.

4. **Маскирование логина и пароля прокси в URL**:
   - Если в `TELEGRAM_PROXY` переданы учетные данные (например, `socks5://user:pass@127.0.0.1:1080` или `http://admin:secret@proxy:8080`), при любом логировании и в `Config.__repr__` URL маскируется до вида:
     `socks5://***:***@127.0.0.1:1080` / `http://***:***@proxy:8080`.
   - Покрыто unit-тестом.

5. **HTML-экранирование пользовательского ввода (`html.escape`)**:
   - Все строки, введенные пользователями (логин, имя и культура установки, имена камер, текст баг-заметки на «*»), экранируются через `html.escape` во всех сообщениях с `parse_mode="HTML"`.
   - Тест: логин `A<B&C` и установка с именем `X<Y>` отображаются без ошибок отправки сообщений Telegram (отсутствие `TelegramBadRequest: can't parse entities`).

6. **Безопасность паролей в журнале и изоляция логов тестов**:
   - Текст сообщения на шаге ввода пароля гарантированно не попадает в JSONL-журнал: ни во входящих событиях (`message`), ни в ошибках, ни в заметках на «*».
   - Тесты **не пишут** в боевой каталог `clients/telegram_bot/logs/` (путь к логам в фикстурах тестов перенаправляется во временную директорию `tmp_path`).
   - После полного тестового прогона каталог `clients/telegram_bot/logs/` отсутствует либо абсолютно пуст.
   - `git status --short` пуст.

7. **Правила раздела 9 `PROJECT.md`**:
   - Быстрые тесты (<3 с на тест, общий сьют <60 с, без реальных sleep).
   - Линтер `ruff check .` и `ruff format --check .` чистые.
   - Формат коммитов: `тип(scope): описание`, scope обязателен (`bot`).
   - `VERSION` не менять (`0.3.1`), теги не ставить.
