## Цель проверки
Провести независимое тестирование и верификацию доработок раунда 3 в Telegram-боте (LIGHT):
1. ArUco: кнопка «Пропустить» отправляет `aruco_size_mm = null` (не задан), текст «по умолчанию 50 мм» убран, ручной ввод `> 0` работает.
2. Старт: при ошибке подключения к Telegram бот не падает, а циклически повторяет попытки по схеме 5, 10, 20, 40, 60... с, выводит понятное сообщение о проверке VPN/TELEGRAM_PROXY и продолжается до успеха или Ctrl+C.
3. Long polling: сетевой сбой во время работы приводит к автоматическому переподключению по той же схеме пауз без завершения процесса; штатная остановка по Ctrl+C.
4. Прокси: логин и пароль в URL прокси маскируются во всех логах (`socks5://***:***@host:port`).
5. HTML-экранирование: все пользовательские строки (логин, имя/культура установки, камеры, заметки «*») экранируются `html.escape`.
6. Безопасность журнала: пароль не попадает в JSONL (ни входящим сообщением, ни ошибкой, ни заметкой «*»). Тесты не пишут в боевой каталог логов; каталог отсутствует/пуст, `git status --short` пуст.
7. Соблюдение правил раздела 9 `PROJECT.md` (<3 с на тест, общий сьют <60 с, без реальных sleep).
