## Структура файлов компонента (`BOT_SPEC.md` разд. 2)
Монолитного `bot.py` нет. Строго реализовать следующую структуру:
```text
clients/telegram_bot/
├── .env.example
├── requirements.txt          # aiogram>=3, httpx, python-dotenv, pytest, pytest-asyncio
├── main.py                   # Точка входа (polling): Bot, Dispatcher, HTTP-клиент
├── config.py                 # Чтение и проверка .env
├── api_client.py             # Асинхронная обёртка над Client API (заголовки, таймауты, разбор ошибок, потоковая загрузка видео)
├── states.py                 # FSM-состояния
├── keyboards/
│   ├── reply.py              # Нижние клавиатуры главного меню (Гость, Biologist, Developer)
│   ├── inline.py             # Inline-клавиатуры карточек, камер, управления, подтверждений
│   └── paginator.py          # Универсальный пагинатор
├── handlers/
│   ├── start_auth.py         # /start, /help, /version, /cancel, авторизация, профиль, выход
│   ├── installations.py      # Список и карточка установок, создание, редактирование, архивация, удаление
│   ├── cameras.py            # Список камер, сканирование, привязка и отвязка
│   ├── control.py            # Ручной снимок, свет, вспышка, тест реле
│   ├── timelapse.py          # Просмотр кадров, ссылка на веб-плеер, сборка и отправка видео
│   └── system.py             # Статус сервера и RPi, интервал автосъёмки, debug_mode
└── utils/
    ├── formatters.py         # Карточки установок, телеметрия RPi, блок DEBUG
    └── errors.py             # Маппер HTTP-ошибок API в понятные сообщения
```

## Функциональность и критерии приёмки
1. **Строгая изоляция и безопасность**:
   - Бот взаимодействует с сервером исключительно через HTTP (`httpx.AsyncClient`) по `docs/API_CONTRACT.md`.
   - В каждый запрос подставляются заголовки:
     `X-Client-Key: <CLIENT_API_KEY>`, `X-Client-Type: telegram`, `X-External-Id: <str(user_id)>`.
   - **Строгий запрет импортов**: `grep -rn "from server\|from shared\|from edge_agent\|from clients.cli\|import server\|import shared" clients/telegram_bot` должен возвращать пустой вывод.
   - Секреты (`TELEGRAM_BOT_TOKEN`, `CLIENT_API_KEY`) и пароли не печатаются в логи и не попадают в git (создать `clients/telegram_bot/.gitignore` для исключения `.env` и `.venv`).
   - При отсутствии обязательных переменных (`TELEGRAM_BOT_TOKEN`, `SERVER_URL`, `CLIENT_API_KEY`) бот завершается с понятной ошибкой в лог с перечислением недостающих.
   - Настоящий Telegram в РФ недоступен: подключение к реальным серверам Telegram в тестах строго запрещено.

2. **Роли и главное меню (`BOT_SPEC.md` разд. 3)**:
   - При `/start` и каждом возврате в меню бот запрашивает `GET /api/auth/me`: `200` -> `biologist` или `developer`, `401` -> Гость.
   - Меню Гостя: `[ 🌱 Установки ]`, `[ 🔑 Войти ] [ ℹ️ Справка ]`.
   - Меню Biologist: `[ 🌱 Установки ] [ 📸 Сделать снимок ]`, `[ 🎬 Таймлапс (видео) ] [ 👤 Профиль / Выход ]`, `[ ℹ️ Справка ]`.
   - Меню Developer: `[ 🌱 Установки ] [ 📷 Камеры ]`, `[ 💡 Свет и реле ] [ 📸 Сделать снимок ]`, `[ 🎬 Таймлапс (видео) ] [ ⚙️ Система ]`, `[ 👤 Профиль / Выход ] [ ℹ️ Справка ]`.
   - Общие команды: `/start`, `/help` (справка и `server_version`), `/version`, `/login`, `/cancel` (сброс FSM).

3. **Универсальный пагинатор (`keyboards/paginator.py`, `BOT_SPEC.md` разд. 4)**:
   - Списки: установки (по 5), камеры (по 5), выбор цели (по 5), кадры таймлапса (по 1 кадру).
   - Кнопка `[ 🌐 Все активные установки ]` для действий, допускающих `all` (снимок, свет, вспышка, тест реле).
   - Пагинатор редактирует сообщение через `edit_message_text` / `edit_message_media`. Компактные `callback_data` (<64 байт), обязательный `await callback.answer()`, игнорирование «message is not modified».

4. **Пользовательские сценарии (`BOT_SPEC.md` разд. 5)**:
   - **Авторизация (5.1)**: Двухэтапный вход: логин -> пароль. Сразу после получения сообщения с паролем бот вызывает `message.delete()` для удаления пароля из чата. Вызов `POST /api/auth/login`. При 401 — предложение повторить, при 429 — сообщение с временем `Retry-After`. Профиль и выход (`POST /api/auth/logout`).
   - **Установки (5.2)**: Список и карточка установки с ролевой проекцией. Создание (Developer, пошаговый мастер FSM: Название, Культура, Light GPIO, Flash GPIO, ArUco). Редактирование (Biologist: название/культура; Developer: все поля + сброс ArUco). Архивация и удаление с подтверждением (при 409 с кадрами — предложение архивации).
   - **Камеры (5.3, Developer)**: Список зарегистрированных камер, кнопка `[ 🔍 Сканировать камеры на RPi ]` (`POST /api/cameras/scan`), показ всех обнаруженных камер (свободна / привязана к установке), привязка и отвязка.
   - **Свет и реле (5.4, Developer)**: Основной свет (вкл/выкл), вспышка (вкл/выкл), тест реле (3 сек) для одной или всех активных установок. Вывод `debug_info` при включённом `debug_mode`.
   - **Ручной снимок (5.5, Biologist / Developer)**: Снимок одной или всех установок (`POST /api/control/snap`). При `status="done"` скачивание `raw_url` и `annotated_url` и отправка альбомом из двух фото с подписью (название, камера, время UTC, площадь). При `status="error"` — текст `result_message`.
   - **Таймлапс (5.6)**:
     - Просмотр кадров: выбор камеры при одновременной съёмке, галерея от самого свежего кадра, переключатель слоёв оригинал/разметка.
     - Сборка видео: выбор установки и камеры, защита от параллельного запуска у одного пользователя, потоковый запрос `POST /api/timelapse/{id}/video` (таймаут чтения 600 с). Проверка лимита `TG_VIDEO_LIMIT = 50_000_000` байт (50 МБ). При превышении — до 5 циклов прореживания со `step = 2, 4, 8, 16, 32` с обновлением статуса пользователю. При укладывании в лимит — отправка видео, при исчерпании — рекомендация скачать через CLI. При 1 плановом кадре (`image/jpeg`) — отправка фото.
   - **Система (5.7, Developer)**: Сводка статуса сервера и RPi, FSM изменения интервала автосъёмки (с выводом warning), переключатель `debug_mode`.

5. **Обработка ошибок (`utils/errors.py`, `BOT_SPEC.md` разд. 6.2)**:
   - Никаких трейсбеков пользователю.
   - Текст `detail` от сервера выводится дословно с понятной подсказкой.
   - Отдельная обработка 401, 403, 404, 409, 422, 429, 503, 504, 5xx и сетевых исключений.
