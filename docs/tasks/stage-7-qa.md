## Цель проверки
Провести независимое тестирование и верификацию Telegram-бота GrowVision на соответствие спецификации `docs/BOT_SPEC.md`, ролевой модели, изоляции компонентов, корректности взаимодействия с Client API и правилам быстрого тестирования `PROJECT.md` (раздел 9).

---

## Проверочный лист (Acceptance Criteria)

### 1. Архитектура и строгая изоляция
- Структура пакета `clients/telegram_bot/` строго соответствует `BOT_SPEC.md` (разд. 2): нет монолитного `bot.py`, код разбит по модулям (`config`, `api_client`, `states`, `keyboards/`, `handlers/`, `utils/`).
- Проверка запрещённых импортов:
  `grep -rn --exclude-dir=.venv "from server\|from shared\|from edge_agent\|from clients.cli\|import server\|import shared" clients/telegram_bot` даёт 0 совпадений.
- Каждый HTTP-запрос передаёт обязательные заголовки: `X-Client-Key: <CLIENT_API_KEY>`, `X-Client-Type: telegram`, `X-External-Id: <user_id>`.

### 2. Безопасность и работа с секретами
- Секреты (`TELEGRAM_BOT_TOKEN`, `CLIENT_API_KEY`, пароли) не логируются и маскируются при отладке/печати `Config`.
- Файл `clients/telegram_bot/.gitignore` корректно исключает `.env`, `.venv`, кэши.
- При отсутствии обязательных переменных бот завершается с понятным сообщением об ошибке, без неперехваченных падений.
- При двухэтапном входе сообщение с паролем немедленно удаляется из чата (`await message.delete()`).

### 3. Ролевая модель и интерфейс
- **Гость** (неавторизован): видит только публичные поля установок, просмотр плановых кадров, `/help`, `/version`, `/login`. Кнопки управления оборудованием скрыты.
- **Biologist**: получает доступ к ручной фотосъёмке (`📸 Сделать снимок`), сборке видео-таймлапсов, редактированию агрономических полей установок.
- **Developer**: полный доступ — управление основным светом и вспышкой, 3-сек тест реле, сканирование и привязка камер, мастер создания, редактирование пинов/ArUco, архивация/удаление установок, телеметрия RPi 5, интервал автосъёмки, `debug_mode`.
- Reply-меню динамически адаптируется под текущую роль пользователя.

### 4. Пагинатор и галерея кадров
- Универсальный пагинатор разбивает списки (установки, камеры, цели съемки) по 5 элементов на страницу.
- Размер `callback_data` строго < 64 байт на всех инлайн-кнопках.
- Галерея плановых кадров: листание по одному кадру от свежих к старым (`◀️ Ранее` / `Позже ▶️`), переключение слоёв (`📷 Оригинал` / `🌿 Разметка нейросетью`) через замену медиа.
- Все callback-запросы завершаются `await callback.answer()`, игнорируется исключение "message is not modified".

### 5. Ручная фотосъёмка (`📸 Сделать снимок`)
- Поддержка выбора конкретной установки или всех активных сразу (`target="all"`).
- Отправка альбома (медиагруппы) из двух фотографий: сырой снимок + снимок с контурами растений.
- В подписи: имя установки, ID камеры, UTC время, площадь растений (в см² при наличии ArUco или в пикселях без него).

### 6. Сборка видео-таймлапса и прореживание
- При 1 плановом кадре отправляется JPEG-фотография с понятным предупреждением.
- Видео до 50 МБ (`TG_VIDEO_LIMIT = 50_000_000` байт) успешно отправляется пользователю как видеозапись.
- При превышении 50 МБ выполняется цикл прореживания (до 5 попыток с коэффициентами `step = 2, 4, 8, 16, 32`) с информированием пользователя.
- При исчерпании 5 циклов выдаётся понятная рекомендация воспользоваться CLI-клиентом (`snap video <id>`).
- Защита от параллельного запуска генерации видео одним пользователем.

### 7. Управление оборудованием и телеметрия RPi 5
- Управление светом и вспышкой (индивидуально и массово).
- 3-секундный тест реле.
- Сканирование камер RPi (`POST /api/cameras/scan`) и привязка к установкам.
- Просмотр статуса системы и подробной телеметрии Raspberry Pi 5.
- Настройка интервала автосъёмки с валидацией.

### 8. Обработка ошибок
- Ошибки сервера (401, 403, 404, 409, 422, 429, 503, 504, 5xx) и сетевые сбои маппятся в понятные сообщения на русском языке с сохранением оригинального `detail`.
- Отсутствие необработанных трейсбеков в чате.

### 9. Быстродействие, чистота репозитория и правила PROJECT.md (разд. 9)
- Unit-тесты бота и E2E тесты выполняются быстро (<3 секунд на тест).
- Общий тестовый прогон репозитория < 60 секунд.
- Тесты не оставляют файлов `growvision.db*` в корне или рабочих директориях.
- `git status --short` остаётся чистым после прогона тестов.
- `ruff check .` и `ruff format --check .` проходят чисто.

- Список выявленных дефектов (если есть) с шагами воспроизведения и ожидаемым поведением
