## Правила скорости и тестов (Раздел 9 PROJECT.md):
1. Тесты быстрые: один тест не дольше 3 с (тест с настоящим ffmpeg до 10 с), весь набор не дольше 60 с. Настоящие ожидания (sleep, ответ RPi 10/15 с, пороги 30/60/90 с) в тестах запрещены: константы времени подменяются через monkeypatch.
2. Состояние для тестов готовится через публичные эндпоинты (RPi онлайн только через POST /api/edge/heartbeat). Прямая запись в БД допустима только для данных, у которых нет эндпоинта.
3. QA и Builder выносят общие фикстуры в conftest.py и используют их повторно.
4. Любой запуск тестов выполняется как `timeout 300 ... pytest`, у вызовов ffmpeg стоит timeout.
5. Две подряд неудачные попытки починить один и тот же тест: стоп, вернуть статус BLOCKED с описанием причины, не делать третью попытку наугад.
6. Чистый git status: после прогона тестов и работы не должно оставаться временных файлов (например `growvision.db*`, файлов в `server/media/` кроме `.gitkeep`). Линтер и форматтер `ruff` должны проходить без ошибок.

## Критерии приёмки:

1. **Общие GPIO-пины в БД (`server/db/models.py`, `server/db/database.py`):**
   - Убрать уникальные индексы `uq_active_light_pin` и `uq_active_flash_pin` — один и тот же GPIO-пин может использоваться в нескольких активных установках одновременно.
   - Сохранить проверку `light_gpio_pin != flash_gpio_pin` внутри одной установки (в модели и валидаторах).
   - При старте БД (`init_db`) безопасно удалять старые индексы `uq_active_light_pin` и `uq_active_flash_pin` через `DROP INDEX IF EXISTS`, если они присутствуют.

2. **Программная синхронизация состояния реле по номеру GPIO-пина (`server/`, `edge_agent/`):**
   - Текущее состояние реле (свет/вспышка) должно отслеживаться и отдаваться в привязке к **номеру GPIO-пина**, а не изолированно по `installation_id`.
   - Если у Установки 1 и Установки 2 задан один и тот же пин (например, `4`), то при переключении этого пина через Установку 1 программное состояние соответствующего реле должно автоматически обновиться и для Установки 2 (и наоборот) — во всех клиентах (API, Telegram-бот, CLI).
   - При запросе состояния реле конкретной установки возвращать фактическое состояние её пинов света и вспышки.

3. **Короткое предупреждение о занятом пине (создание и редактирование установки — `server/`, `clients/telegram_bot/`, `clients/cli/`):**
   - При создании новой установки и при редактировании пинов существующей установки, если указанный пин уже используется другой активной установкой (как свет или как вспышка), **не блокировать** сохранение, а возвращать/показывать короткое предупреждение с **названием установки** (`installation.name`, не культурой):
     `⚠️ Пин 4 уже занят («Установка 1»). Реле будут общими.`
   - Если пин занят несколькими установками — перечислить их названия через запятую (например: `⚠️ Пин 4 уже занят («Установка 1», «Установка 2»). Реле будут общими.`).
   - Сервер возвращает предупреждения (например, поле `warnings: list[str]` в ответе `POST /api/installations`, `PATCH /api/installations/{id}` или в карточке ответа).
   - В Telegram-боте при создании/редактировании показывать это предупреждение пользователю (в сообщении подтверждения / в карточке).
   - В CLI выводить предупреждение в консоль при создании (`unit add`) и редактировании (`unit edit`).

4. **Переименование пользователей (`server/api/auth.py`, `clients/telegram_bot/`, `clients/cli/`):**
   - Добавить возможность изменить отображаемое имя (`login`, Имя и Фамилия) без изменения `external_id` (`telegram_id`), роли и истории сессии:
     - `developer` может переименовать **любого** пользователя (эндпоинт `PATCH /api/auth/sessions/{session_id}` с телом `{"login": "..."}` + кнопка «✏️ Переименовать» в карточке пользователя в разделе «👥 Сессии» бота + команда `auth rename <session_id> <new_name>` в CLI).
     - `biologist` может переименовать **только самого себя** (эндпоинт `PATCH /api/auth/me` с телом `{"login": "..."}` + кнопка «✏️ Изменить имя» в профиле бота `/profile`).
     - Попытка переименовать чужого пользователя биологом возвращает 403 Forbidden.
   - Валидировать непустую строку (1..64 символов, strip), применять `html.escape` при выводе в Telegram-боте.

5. **Документация и тесты:**
   - Обновить `docs/DB_SCHEMA.md`, `docs/API_CONTRACT.md`, `docs/BOT_SPEC.md`, `docs/CLI_SPEC.md`, `docs/USER_GUIDE.md`.
   - Покрыть unit- и E2E-тестами:
     - создание/редактирование двух установок с общим пином и получение предупреждения;
     - программную синхронизацию состояния реле при переключении общего пина;
     - переименование себя биологом;
     - запрет переименования чужого пользователя биологом (403);
     - переименование любого пользователя разработчиком.
   - Все тесты репозитория зелёные, `ruff check .` и `ruff format --check .` чистые, `git status --short` пуст.
