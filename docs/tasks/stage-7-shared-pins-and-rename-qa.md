## Цель проверки
Провести независимое тестирование и верификацию реализации Этапа 7.4:

1. **Общие GPIO-пины в БД:**
   - Отсутствие уникальных индексов `uq_active_light_pin` и `uq_active_flash_pin` — один и тот же пин разрешён в нескольких активных установках.
   - Проверка `light_gpio_pin != flash_gpio_pin` внутри одной установки по-прежнему блокирует сохранение (422/ValidationError).
   - Безопасное удаление старых индексов при старте на существующей БД.

2. **Программная синхронизация состояния реле по номеру GPIO-пина:**
   - Состояние реле связано с номером пина. При переключении реле на Установке 1 состояние пина на Установке 2 с тем же пином автоматически меняется в API, боте и CLI.

3. **Предупреждения о занятом пине:**
   - При создании/редактировании установки с уже занятым пином операция не блокируется, возвращается предупреждение с именем установки:
     `⚠️ Пин 4 уже занят («Установка 1»). Реле будут общими.` (или список названий через запятую при нескольких установках).
   - Предупреждение отображается в ответе API, в Telegram-боте и в CLI.

4. **Переименование пользователей:**
   - Биолог переименовывает себя через `PATCH /api/auth/me`, кнопка «✏️ Изменить имя» в профиле бота.
   - Биолог получает 403 при попытке переименовать чужого пользователя.
   - Разработчик переименовывает любого пользователя через `PATCH /api/auth/sessions/{id}`, кнопка «✏️ Переименовать» в карточке сессии бота, команда `auth rename <id> <name>` в CLI.
   - Валидация непустого имени и экранирование `html.escape`.

5. **Правила скорости и тестов (Раздел 9 PROJECT.md):**
   - Быстрые тесты (<3 с на тест, весь набор <60 с, без `sleep`).
   - Чистый `git status --short`, линтер `ruff check .` и `ruff format --check .` чистые.
