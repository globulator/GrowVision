# Задача: Этап 8.5 / Унификация входа без личного пароля, фиксы таймлапса и отмены бота, фиксы Web SPA и изоляция mock-режима
Режим: FULL
Ветка: stage-8/ux-and-mock-isolation

Цель:
1. Унификация авторизации:
   - Полное удаление `password_hash` из БД (`users`), моделей SQLAlchemy, схем Pydantic и документации.
   - Единая модель входа: вход по `DEVELOPER_PASSWORD` (роль `developer`) или по одноразовому коду инвайта биолога (роль `biologist`).
   - Синхронизация `full_name` из Telegram: имя пользователя подтягивается из Telegram-контактов (`first_name` + `last_name` или `username`) при авторизации.
   - Подтверждение при выходе: стилизованная модалка с подтверждением выхода в Web SPA (без alert/confirm).
2. Telegram-бот:
   - Кнопка «Отмена» доступна на ВСЕХ шагах FSM создания и редактирования установки (сброс состояния и возврат в меню).
   - При ошибке валидации (неверный формат, занятый пин и т.д.) сохранять текущий шаг FSM, не сбрасывая процесс и не заставляя начинать заново.
   - Таймлапс: расчет целевой частоты кадров строго под 30 FPS (без пресетов 5/10/15/30 сек). Равномерное прореживание при превышении 30 FPS с выводом понятного оповещения пользователю.
3. Web SPA:
   - Исправление 404 галереи: проверка маршрутов и параметров загрузки кадров.
   - Исправление отображения тестового снимка: корректный рендеринг изображения и разметки.
   - Единый стиль медиа-заглушек (#161e29, аккуратные SVG-иконки, тексты с легким юмором при отсутствии кадров или камер).
   - При сетевом обрыве — плашка «Сервер недоступен» / тост.
   - SVG-анимация жизненного цикла растения (семечко -> росток -> взрослое растение) вместо банального спиннера.
   - Инварианты: 0 эмодзи (только SVG), 0 alert/confirm/prompt, 0 X-Client-Key, 0 CDN.
4. Edge-агент и изоляция Mock-режима:
   - `HARDWARE_MODE=auto` по умолчанию: автоопределение реальной Raspberry Pi (наличие `/proc/device-tree/model` с Raspberry Pi или `gpiod` / `picam`) vs эмуляция (Mock) на ПК разработчика.
   - В Web SPA блокировать переключение в боевой режим `rpi`, если на плате нет реального оборудования (сообщение о недоступности).
   - При работе в Mock-режиме использовать отдельную временную SQLite БД `growvision_mock.db` (или изолированную тестовую базу) для установок/кадров, но с сохранением пользователей и сессий в основной БД.
   - Беспарольный `sudo` для перезапуска служб GrowVision в скриптах установки и обновления (`/etc/sudoers.d/growvision`).
5. Документация и тесты:
   - Обновить `docs/DB_SCHEMA.md`, `docs/API_CONTRACT.md`, `docs/USER_GUIDE.md`, `docs/WEB_SPEC.md`.
   - Полный прогон unit- и E2E-тестов.
   - Handoff: `docs/handoff/stage-8-5-ux-and-mock.md`.
