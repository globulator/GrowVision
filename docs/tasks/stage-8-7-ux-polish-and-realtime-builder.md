Критерии приёмки:
1. Регистрация и вход Web ↔ Telegram (`server/api/auth.py`, `clients/web/js/auth.js`, `clients/web/index.html`):
   - Обязательное подтверждение кодом в Telegram для новых пользователей:
     - Если пользователь ещё не зарегистрирован в системе (`User` отсутствует в БД) и пытается войти через форму входа (`POST /api/auth/web/login`), сервер НЕ должен пускать его без подтверждения кодом в Telegram и не должен создавать сессию. При попытке входа незарегистрированного пользователя `/api/auth/web/login` должен возвращать HTTP 403 или структурированный ответ с кодом `telegram_verification_required` / `not_registered`, переводящий веб-интерфейс на сценарий подтверждения через 6-значный код в Telegram (`register/start` -> бот отправляет код -> `register/verify` -> `register/complete`).
     - Не перезаписывать `user.login = full_name` без надобности.
   - Рекомендуемое имя из Telegram с возможностью редактирования:
     - Эндпоинт `POST /api/auth/web/register/start` (`server/api/auth.py:536`) возвращает `recommended_name` (собранное из `first_name` и `last_name` из `TelegramContact`).
     - На шаге завершения регистрации в `clients/web/js/auth.js` поле `reg-full-name` предзаполняется этим `recommended_name` с подсказкой «Рекомендуемое имя из Telegram (можно изменить)», чтобы пользователь мог отредактировать его перед подтверждением.
   - Ссылка на бота вместо длинного текста:
     - В `#modal-login` и `#modal-register` (`clients/web/index.html`) громоздкий текст заменить на лаконичную строку со ссылкой на Telegram-бота (`https://t.me/<BOT_USERNAME>`, `target="_blank" rel="noopener"`), чтобы пользователь мог в 1 клик открыть бота, нажать `/start` и получить код. Имя бота отдавать с сервера в `/api/auth/web/me` или `/api/health` (или `GET /api/version`).

2. Галерея и рекомендованная длительность таймлапса (`clients/web/js/gallery.js`, `clients/web/index.html`):
   - Реальное отображение кадров в Галерее: исправить `clients/web/js/gallery.js`, чтобы вместо заглушки `"Кадр N"` рендерился и отрисовывался реальный `<img>` с URL кадра из API (с обработчиком `onerror`, переключающим область просмотра на заглушку битого кадра).
   - Рекомендованная длительность таймлапса при открытии галереи:
     - В окне галереи (блок экспорта таймлапса/GIF) сделать числовое поле ввода длительности в секундах (`min="1"`, `step="1"`), куда пользователь может вписать своё значение.
     - При открытии галереи и переключении камеры автоматически вычислять и подставлять рекомендованную длительность: `recommended_sec = Math.max(1, Math.round(framesCount / 15))` (целевые ~15 fps, не меньше 1 сек).
     - Рядом в реальном времени выводить итоговый FPS (`framesCount / durationSec`) и inline-предупреждения:
       - если `framesCount / durationSec > 30` — предупреждение о прореживании до 30 fps;
       - если `durationSec > framesCount` (< 1 fps) — подсказка, что каждый кадр удерживается дольше 1 с;
       - если значение `< 1` или нецелое — inline-ошибка и блокировка кнопки экспорта.

3. Классифицированная обработка исключений в Web SPA (`clients/web/js/*.js`):
   - Сохранить `showError` (`clients/web/js/dialogs.js`) только как страховочный перехватчик для непредвиденных исключений (HTTP 500, необработанные ошибки JS), чтобы интерфейс не падал молча.
   - Убрать все рутинные `showError` и `showConfirm`:
     1. Обрыв сети / недоступность сервера (`TypeError: Failed to fetch`, 502–504): показывать баннер `#server-offline-banner` под шапкой; в `units.js:196` не вызывать `showError`; в `gallery.js:76-79` и `test_snap.js:101-102` НЕ закрывать модальное окно и не вызывать `showError`, а оставлять модалку открытой с медиа-заглушкой обрыва сети и заблокированными кнопками.
     2. Пустая галерея и офлайн RPi: в `gallery.js:64-67` при `frames.length === 0` НЕ закрывать галерею и не вызывать `showError` — показывать внутри рамки галереи заглушку пустого альбома и блокировать кнопки плеера/экспорта; в `test_snap.js:101-102` при 503 / `agent_offline` показывать внутри окна снимка заглушку недоступной камеры без попапа.
     3. Ошибки форм и валидации (`auth.js`, `rpi_setup.js`): выводить ошибки валидации, неверного кода/пароля и копирования inline-текстом красного цвета внутри активной формы под полем ввода (без `showError`).
     4. Подтверждение выхода (`app.js:83`): удалить `showConfirm` при нажатии «Выйти» — заменить на компактное inline-подтверждение в шапке рядом с именем пользователя (`Выйти?` -> `Да` / `Отмена`) с пояснением о необходимости пароля/кода для повторного входа.

4. Тематические медиа-заглушки и весёлая загрузка (`clients/web/js/`, `clients/web/css/`):
   - Удалить старый логотип из всех заглушек (`units.js`, `gallery.js`, `test_snap.js`). Использовать только логически связанные пары «тематическая SVG-иконка + фраза», выбираемые случайно (`Math.random()`) при каждом показе:
     - Категория A (0 кадров в установке или галерее):
       - «Растение застеснялось. Фотографий нет» (SVG ростка/листа);
       - «Похоже, фотограф забыл снять крышку с объектива» (SVG закрытого/перечёркнутого объектива);
       - «Здесь ничего нет — или просто кто-то прошёлся по клавиатуре и стёр базу» (SVG кота у клавиатуры).
     - Категория B (RPi / камера недоступна):
       - «Картинки не будет — фотограф сбежал» (SVG отключённой камеры);
       - «Камера ушла на перерыв. Проверьте подключение платы» (SVG перечёркнутого фотоаппарата).
     - Категория C (Обрыв связи с сервером):
       - «Возможно, кто-то перегрыз провод» (SVG мыши / разорванного кабеля);
       - «Связь с сервером временно оборвалась» (SVG разъединённого штекера).
     - Категория D (Битый файл / ошибка декодирования кадра `onerror`):
       - «Кадр потерялся по дороге с грядки» (SVG повреждённого кадра).
   - Единый стиль текста на всех заглушках (включая `#modal-test-snap`): серый `#94a3b8`, одинаковый размер шрифта, по центру (`text-align: center`, `max-width: 280px`, `margin: 0 auto`).
   - Весёлые фразы при загрузке тестового снимка (`test_snap.js`): случайный выбор при каждом снимке (например, *«Ждём, когда растение улыбнётся на камеру...»*, *«Наводим резкость на самый фотогеничный листик...»*, *«Просим росток не моргать...»*, *«Ищем удачный ракурс для фотосессии...»*), сохранив зацикленную SVG-анимацию роста растения.

5. Автоопределение RPi / Mock и честный онлайн-статус платы (`edge_agent/config.py`, `server/api/edge.py`, `clients/web/js/rpi_setup.js`):
   - Исправить `is_raspberry_pi()` в `edge_agent/config.py`: проверять одновременно два условия: `/proc/device-tree/model` существует и содержит `"Raspberry Pi"` (case-insensitive) И библиотека `gpiozero` доступна (`importlib.util.find_spec("gpiozero") is not None`). Иначе `HARDWARE_MODE=auto` обязан выбирать `"mock"`.
   - Честный онлайн-статус и режим платы в `server/api/edge.py` и `rpi_setup.js`:
     - Сервер считает `rpi_connection == "online"` ТОЛЬКО если последний heartbeat от агента получен не более 35 секунд назад; если агент остановлен или heartbeat устарел — `"offline"`.
     - В heartbeat передавать и сохранять фактический `hardware_mode` (`"rpi"` или `"mock"`).
     - В `clients/web/js/rpi_setup.js` не подставлять `'rpi'` по умолчанию при отсутствии телеметрии (показывать фактический режим или `'Не подключено'`, для эмулятора — `Эмулятор (mock)` с пометкой `(mock)` в имени устройства). Блокировать переключатель режима `rpi/mock` (`disabled`), если не подключена реальная плата `rpi` или агент в режиме `mock`.
