## Правила скорости и тестов (Раздел 9 PROJECT.md):
1. Тесты быстрые: один тест не дольше 3 с (тест с настоящим ffmpeg до 10 с), весь набор не дольше 60 с. Настоящие ожидания (sleep, ответ RPi 10/15 с, пороги 30/60/90 с) в тестах запрещены: константы времени подменяются через monkeypatch.
2. Состояние для тестов готовится через публичные эндпоинты (RPi онлайн только через POST /api/edge/heartbeat). Прямая запись в БД допустима только для данных, у которых нет эндпоинта.
3. QA и Builder выносят общие фикстуры в conftest.py и используют их повторно.
4. Любой запуск тестов выполняется как `timeout 300 ... pytest`, у вызовов ffmpeg стоит timeout.
5. Две подряд неудачные попытки починить один и тот же тест: стоп, вернуть статус BLOCKED с описанием причины, не делать третью попытку наугад.
6. Чистый git status: после прогона тестов и работы не должно оставаться временных файлов (например `growvision.db*`, файлов в `server/media/` кроме `.gitkeep`). Линтер и форматтер `ruff` должны проходить без ошибок.

## Критерии приёмки:

1. **Фикс прокси в Edge-агенте (`edge_agent/client.py`):**
   - Во всех клиентах `httpx.Client` (и `AsyncClient`, если используется) явно задать `trust_env=False`, чтобы локальные вызовы и запросы через NetBird/VPN не падали при наличии активного `ALL_PROXY` / `HTTP_PROXY` / `HTTPS_PROXY`.

2. **GPIO-пины и состояние света по умолчанию (`server/`, `edge_agent/`, клиенты):**
   - **Разрешить `light_gpio_pin == flash_gpio_pin`** внутри одной установки:
     - Убрать валидацию и ограничения на неравенство пинов в моделях БД (`Installation`), Pydantic-схемах и хэндлерах бота/CLI/веба.
   - Если пины света и вспышки совпадают:
     - При создании и редактировании установки выводить предупреждение: пины света и вспышки совпадают, управляется только свет, при съёмке он не выключается.
     - В `edge_agent` при захвате кадра (`SNAP` и плановая съёмка) для установки с одинаковыми пинами **не выключать свет** и не переключать реле повторно.
   - **Состояние по умолчанию:**
     - При создании новой установки (и при старте системы/агента для активных установок) сигнал на пин света по умолчанию **ВКЛ (`True`)**, а на пин вспышки — **ВЫКЛ (`False`)**.
     - Во время съёмки (только если пины разные): свет ВЫКЛ, вспышка ВКЛ, после снимка возврат в исходное состояние (свет ВКЛ, вспышка ВЫКЛ).

3. **Ограничение прав Гостя (сервер, Web SPA, Telegram-бот):**
   - На сервере в `GET /api/installations` для роли `guest` полностью запретить чтение архивных установок: всегда возвращать только активные установки (`is_archived == False`), даже если передан параметр `include_archived=true`.
   - В Web SPA и Telegram-боте для роли `guest` скрыть элемент/кнопку «Показать архивные». Гость видит только активные установки: название, культуру, последний кадр и кнопку перехода в галерею/таймлапс.

4. **Компактный UX и визуал Web SPA (`clients/web/`):**
   - **Уменьшение количества вкладок:**
     - Убрать отдельную вкладку «Плеер». У Гостя остаётся **только одна вкладка «Установки»**.
     - Вкладка «Свет и реле» (для Биолога/Разработчика) содержит **только общие настройки для всех установок сразу** (общий свет / общая вспышка / тест реле). Индивидуальное управление установкой — непосредственно на её карточке.
   - **Карточка установки:**
     - Сразу отображать **последний кадр** установки прямо на карточке (вместе с названием, культурой, площадью, быстрыми действиями по роли) и кнопку **«Галерея»**.
   - **Модальное окно «Галерея и таймлапс»:**
     - При открытии показывать плавную **анимацию ожидания/загрузки** и статус `Загружено X из N`.
     - Внутри модалки: покадровый просмотр, плеер таймлапса, селектор камеры, переключатель слоя (`Оригинал` / `Разметка`), навигация по кадрам, параметры и кнопка **«Скачать»** (сборка и загрузка MP4).
     - **Связанный расчёт длительности и FPS:** `duration = frames / fps`, `fps = frames / duration`. Изменение продолжительности обновляет FPS, изменение FPS обновляет продолжительность. Валидация: **`fps >= 1`** (длительность не может превышать количество кадров).
   - **Визуальное обновление (полностью оффлайн, без сторонних CDN):**
     - Добавить мягкий размытый растительный фон (локальный SVG/CSS в `clients/web/assets/` с эффектом `blur`).
     - Плавные анимации ожидания (спиннеры/скелетоны) при загрузке данных, галереи и сборке видео.
     - Заменить эмодзи на кнопках на аккуратные **inline SVG-иконки** (на ключевых кнопках иконка + текст, на компактных действиях — иконка с `title`/`aria-label`).

5. **Объединение галереи и таймлапса в Telegram-боте (`clients/telegram_bot/`):**
   - Убрать отдельный раздел «Таймлапс» из главного меню бота.
   - Запуск сборки таймлапса перенести внутрь существующей **Галереи** через кнопку **«Сформировать таймлапс»** (или «Скачать таймлапс»).
   - Интерактивный диалог:
     1. Ввод продолжительности (с кнопкой оставить по умолчанию).
     2. Настройка FPS (связанная с длительностью, валидация `fps >= 1`).
     3. Экран сводки с параметрами (установка, камера, кадры, длительность, FPS, слой) и кнопками «Подтвердить» / «Отмена».
     4. После подтверждения — сборка через сервер и отправка MP4.

6. **Документация и тесты:**
   - Обновить `docs/WEB_SPEC.md`, `docs/BOT_SPEC.md`, `docs/API_CONTRACT.md`, `docs/DB_SCHEMA.md`, `docs/USER_GUIDE.md`.
   - Покрыть unit- и E2E-тестами все изменения (включая `trust_env=False`, `light_gpio_pin == flash_gpio_pin`, свет по умолчанию ON, фильтрацию архива для гостя, валидацию `fps >= 1`, обновленный флоу таймлапса в боте и Web).
   - Все тесты зеленые, `ruff check .` и `ruff format --check .` чистые, `git status --short` пуст.
   - Версию в `VERSION` во время реализации НЕ поднимать (бамп до 0.4.1 и тег v0.4.1 выполнит Coordinator после приёмки QA и слияния в main).
