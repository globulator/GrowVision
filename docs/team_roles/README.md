# Связка агентов: Coordinator + Builder + QA-Tester + Scribe

Универсальная схема разработки по этапам. Всё, что зависит от проекта, лежит в `docs/PROJECT.md`. Сами роли от проекта не зависят.

## Раскладка файлов

```text
docs/team_roles/
  coordinator.md  builder.md  qa_tester.md  scribe.md   <- роли
docs/
  PROJECT.md        паспорт проекта (защищённый, заполняется на Этапе 0)
  STATE.md          состояние этапа (пишет только Coordinator)
  qa_log.md         журнал QA (создаёт и ведёт QA-Tester)
  agent_questions.md, user_tasks.md   реестры (ведёт Scribe)
  tasks/ handoff/ stage_reports/      создаются по ходу работы
```

## Как начать

1. Положите папки `docs/team_roles/` и `docs/` в корень репозитория.
2. Запустите агента Coordinator с инструкцией «Следуй `docs/team_roles/coordinator.md`».
3. Он проведёт Этап 0: задаст вопросы, заполнит `PROJECT.md`, предложит план этапов. Подтвердите «ОК».
4. Дальше он сам запускает Builder-ов, QA и Scribe. Вам он пишет короткие сводки и зовёт, только когда нужно ваше решение (`Q-…`) или действие (`T-…`).

## Если Coordinator не умеет сам запускать агентов

Работайте в ручном режиме (описан в `coordinator.md`, раздел 7): он записывает карточку задачи в `docs/tasks/` и говорит, какого агента запустить. Вы запускаете отдельную сессию с нужным файлом роли и приносите его короткий отчёт обратно. Состояние не теряется, потому что оно лежит в `STATE.md`.

## Рекомендации для лёгких моделей (Flash)

- Одна роль = одна сессия. После закрытия этапа начинайте новые сессии: Builder и QA со «свежим» контекстом работают лучше.
- Держите этапы маленькими (до ~10 файлов) и с проверяемыми критериями приёмки. Это главный рычаг качества.
- Если есть возможность использовать более сильную модель хотя бы в одном месте: QA-Tester (и составление спецификаций на Этапе 0). Тогда Builder и QA не будут пропускать одни и те же ошибки.
- Если агент зациклился или отвечает невпопад — перезапустите его на той же карточке с handoff-файлом (`coordinator.md`, пункт I).

## Что изменилось по сравнению с первой версией

- Добавлен Этап 0 и `PROJECT.md`: роли больше не привязаны к конкретной архитектуре.
- Добавлен `STATE.md`: Coordinator не зависит от своего контекста.
- Лимит в 3 круга `FAIL`, затем эскалация к пользователю.
- Замкнуты петли `DEFERRED`, `BLOCKED` и ошибок в спецификации (`SPEC_ISSUE`).
- Регрессионный набор: каждый найденный баг превращается в автотест (QA пишет в `qa_tests_dir`).
- У Scribe один понятный набор триггеров-событий.
- Ветки и worktrees для параллельных Builder-ов.
- Лёгкий режим для мелких правок.
- Роли переписаны под лёгкие модели: нумерованные шаги, чек-листы, шаблоны и примеры вместо общих призывов.
